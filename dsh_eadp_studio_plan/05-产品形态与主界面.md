# 5. 产品形态与主界面

> 来源：2026-10-13 产品形态讨论与主界面示意（eadp-core-design 工作区 · 项目场景页截图）。本册只记录已确认的产品形态决策；界面示意中尚未设计的场景相关概念不在此记录，待设计确认后另行补充。终态为基于官方 DSH 桌面工程、内置专用插件的 eadp 工作台单一安装包，打开即五阶段 Studio 主界面；协同后端为企业集中部署的固定服务。界面细节以实际实现为准；语义未定项汇总在 [04-待确认与待实测清单.md](04-待确认与待实测清单.md)。

## 5.1 产品形态定位

- **桌面客户端即产品**：交付一个可安装的 eadp 项目工作台，基于固定官方 DSH 桌面工程构建，内置并默认启用专用插件、模板和必要工具链。用户无需先下载 DSH 或进入插件管理；安装后从工作台快捷方式打开即进入五阶段 Studio 主界面（全局 `main` 面板满窗）。宿主与内置插件统一版本、安装和更新；完整安装包与满窗形态由 G0-1 验证，承载确认无法满足时按 1.4 止损条款处理。
- **可配置模型**：模型经宿主会话配置（供应方、模型与密钥沿用既有模型策略、审批与取消管线），工作台不另建模型接入层或 Agent loop。
- **固定后端**：协同后端由企业集中部署，客户端连接固定服务地址，多作者共享占用与协同状态；不在用户侧部署。
- **项目入口**：先登录协同后端，新建时填写项目名/仓库路径并选择本人可建仓群组；后端创建 private 空库并分配既有绑定账号，Host 使用本机 Git 凭据初始化/推送，后端复核后 ready。也可选择后台已有项目，或用其已登记且获授权的 Git 地址克隆并校验。pending 项目展示初始化进度或恢复入口，不能认领业务任务。每项目默认包含 `场景/`、`需求/`、`原型代码/` 三个业务文件夹，根目录的项目资产、基线及交接清单文件按 2.3 管理。
- **持续 AI 交互**：五阶段均保留可见的官方 Agent 交互入口，当前项目、场景、需求及固定输入随任务绑定；不要求用户离开工作台自行组织提示词。原型展示参考 bolt.new 的对话、源文件和运行预览协作方式，具体会话承载能力由 G0 验证，不预设目标宿主已有可嵌入的会话组件。
- **原型入口（标题栏）**：随两种状态判定——本地服务启动状态：本地服务运行中显示「本地原型」；远程服务部署状态：本地未运行但远程服务已部署显示「远程原型」；均无则显示「未运行」。点击直接跳转浏览器查看，不展示技术地址；本地预览服务仍仅监听 loopback（2.7.3、3.4）。

## 5.2 主界面结构

| 区域 | 界面内容 | 语义与契约挂接 |
| --- | --- | --- |
| 标题栏 | 原型入口：「本地原型」/「远程原型」/「未运行」 | 按本地服务启动状态与远程服务部署状态判定：本地运行显示本地原型，本地未运行且远程已部署显示远程原型，均无显示未运行；点击直接跳转浏览器查看（3.4 预览、3.5 单一当前站点）；不展示技术地址 |
| 顶部 | 工作空间/项目选择器、新建项目、通过 Git 地址获取项目、协同后端登录身份（当前测试管理员） | 项目初始化、克隆、切换和权限校验（2.3 项目行、3.2 步骤 1–2）；协同会话与持久绑定 GitLab 账号（2.5） |
| 左侧导航 | 五阶段：项目场景 → 需求协同 → 原型展示 → 基线确认 → 交接清单；底部 GitLab 连接状态与当前分支（`GitLab Connected / branch: main`） | 1.2 五阶段主流程；2.2.1 代码托管边界 |
| 交互区 | 可见的官方 Agent 对话入口、当前任务及输入版本、待确认问题 | 复用官方会话、审批与取消；在对话中明确表达“确认”与按钮归一到 Host 的同一确认动作，须绑定明确成果；Agent 无权自行确认 |

## 5.3 各菜单的操作闭环

### 项目场景与需求协同

项目场景菜单每次“新建场景”创建 `场景/<scenario-id>.md`。作者与 AI 整理内容，可随时明确要求确认或点击确认按钮。Host 固定内容、推送 Git，向协同后端提交文件内容 SHA-256 哈希、固定 Git 引用及必要控制元数据；业务 API 不接收上传正文，后端先按协同操作者绑定的 GitLab 成员权限验权，再临时读取固定 MD 校验，不持久保存正文，见 [临时读取校验决策](../docs/adr/0002-backend-transient-git-validation.md)。读取或校验失败时不接受确认。仅 Git 推送成功时显示“待同步”，后端接受后才显示“已确认”。

场景确认成功后默认调用 AI Agent 拆分需求，呈现生成完成的候选标题。用户选中某个标题后预留正式需求 ID、取得设计占用，进入需求侧交互并形成 `需求/<requirement-id>.md` 草稿；未选候选保持本地草稿，不视为已确认需求，也不提前占用全部候选。作者确认需求时同样先推送 MD，再上报哈希。后端接受且占用、前置完成条件满足后，默认调用编码 Agent；条件不足时保留确认结果并展示等待原因。已有场景修改仍执行关联需求冻结和完整联动批次确认。

新增场景和需求时明确记录业务分类与状态；列表、成果视图及复用操作显示固定版本、可复用资格和原因，区分材料确认、原型完成与复用资格。经必需检查、正文推送 Git 且后端接受阶段确认的材料可以独立沉淀，同时自动取得复用资格，不必等待原型完成，无二次资格按钮或审批；确认与资格分别记录，重复确认事件不恢复后续已停用资格。检索和显式采用完整场景包或需求包在既有场景/需求菜单内完成：选择固定来源、核验资格、绑定目标任务，采用后调整并重新检查确认，不新增第六阶段，不继承来源确认或完成状态。

原有确认检查要求核心业务规则与验收条件明确；缺失时显示具体待补项并保留草稿，不确认或授予资格，不由 AI 编造补齐。其他待澄清可随材料保留，但在成果与采用视图显示限制及不适用范围，不增加二次审批。停用显示资格变化而不删除正式材料、固定版本或来源证据；正式 Git 可达固定引用及后端元数据/事件/来源证据长期保留。临时构建、缓存和任务现场单独清理，遇未提交、未推送成果或在途任务唯一现场时阻止清理并显示原因，不要求业务用户操作备份平台。

客户端显示和提交结果须来自后端状态与 Git 固定材料的核验；新草稿不可采用，编辑新草稿不暂停旧固定版本已有资格。显式停用只有后端接受后才显示已生效并阻止新的采用，受理前不能冒称生效；历史固定版本及已复制且独立维护的目标保留来源，不自动撤销。所有具有该资产编辑权限的成员均可停用或恢复，由后端按既有可信身份与该资产编辑权限受理并记录操作者、原因和时间，不以 Git 凭据代替授权；恢复不重做确认或基线。资格不足或状态过期时展示原因，不能仅因本地操作或显示就判定可复用。

浏览或选中不显示为已采用；以后端接受采用记录为界，停用生效时尚未接受的采用阻止，已接受的采用保留固定来源继续，来源 Git 读取授权仍须满足。采用受理与复用成功分别显示；目标通过自身检查、确认并由后端接受后，记录目标最终固定版本及来源，失败或取消不显示成功。新增场景/需求选择已有项目业务分类，所有具有项目编辑权限的成员均可维护词表；编辑既有分类保留固定材料历史分类及 ID，不自动改写历史正文。实际词表值、状态编码和交互细节由 G0 输入及验证，不预设分类层级、企业库、具体按钮或额外审批。

### 原型展示

原型展示始终标明当前需求、确认输入和本地运行状态，提供三个相互关联的区域：

| 区域 | 职责 |
| --- | --- |
| AI 对话 | 描述页面及交互修改、回答 Agent 问题、查看修改反馈；官方会话保持可见或可直接展开，执行沿用官方审批与取消 |
| 源文件 | 浏览当前需求工作树中的文档与原型源文件、查看变更；不要求非研发用户阅读或编辑源码才能完成任务 |
| 运行预览 | 运行当前需求成果并操作页面，显示启动、失败、停止及待更新状态；本地服务仅监听 loopback，不随他人提交自动切换 |

用户对预览不满意时直接在本菜单与 AI 交互修改。若修改与已确认需求冲突，展示冲突及需求修订候选，并保留代码、预览和会话现场；用户重新确认需求 MD、推送 Git 且后端接受新哈希后，重新绑定输入及前置依据，再继续编码和完成确认。不能把代码修改自动当成需求确认；涉及场景范围时按场景联动规则处理。

用户满意后点击“确认”，明确当前完成的一个需求；若未绑定唯一需求，先选择该需求。Host 检查并提交该需求相关代码和文档，自动集成到完整项目快照，不携带其他需求未确认的工作。直接路径不再要求手工合并；可选评审仍针对固定候选，满足条件后执行同一完成流程。Git 合并及后端完成确认均成功后才展示有效基线，待同步、冲突或拒绝须如实显示。

本菜单提供“部署到远端”，只发布项目当前已确认基线的固定原型代码版本到项目配置的唯一目标；未确认工作不可发布。按钮显示待部署、部署中、已部署或失败，区分本地预览版本、当前基线与远端实际部署版本。发布依然执行独立授权、构建与远端安全检查，不要求业务作者输入命令或维护服务器配置。

### 基线确认与交接清单

“基线确认”是原型确认后的结果视图，展示固定基线、已完成需求和确认依据，不重复要求用户确认。场景及需求 MD 的阶段提交只保存阶段确认材料，不生成原型基线。

有效基线形成后，由 Host 后台任务默认调用 AI Agent 整理可交付清单，正文进入 Git，后端仅保存哈希、固定引用及控制状态；不新增服务端 Agent 或正文托管。交接菜单呈现清单生成状态和结果，用户可以补充限制、待澄清项并确认交接；清单生成失败可按相同基线重试，不撤销已完成基线，也不冒充交接已完成。固定资料和“项目当前演示”链接分别标识，避免把当前演示当作历史页面快照。

## 5.5 术语对照

- **工作空间**：用户选择和管理本地项目的入口；一个项目对应一个过程资产 Git 仓库。宿主执行时的 workspace 绑定当前项目或当前需求的隔离工作树，不能把多个项目当成一个资产仓库。
- **AI Agent**：宿主官方会话中的智能体；本项目过程、资产与文档均由人与 AI Agent 协作完成，文档统一写作"AI Agent"。
