首任务必须交付：

1. 可复现的最小工程、已核验的构建/运行入口和依赖锁定；源码、工具和构建件版本/校验值可追溯。
2. 真实接口清单：每项记录固定上游 SHA、源文件路径、symbol、参数/返回值及权限/生命周期限制；未知项明确标记，不填假接口。
3. 最小 Studio 实机画面，以及真实会话输入、事件、审批、取消、重启恢复的步骤和结果；使用 DeepSeek `deepseek-flash` 经 DSH 原生模型配置，真实调用未执行时保持未验证。
4. Linux 构建/检查与 Windows 原生运行结果分开记录；Windows 目标 OS/CPU 及实际依赖必须入证据。缺 Windows 环境时可完成 Linux 部分，但不得标记 Windows 已通过。
5. 失败项、实际原因和修正后的复验结果；缺独立复验标记 `self_review`。证据组织、脱敏及字段沿用 07，不上传完整会话、提示词或草稿。

**该切片完成不等于整个 G0-1 通过。** [G0-1](G0-1-最小插件与接口清单.md) 仍须完成干净 Windows 机单包安装、签名、首启、随包组件、升级、卸载、已有 DSH 共存及完整接口验收。最终交付须为内置默认启用插件、模板和所需运行时的工作台安装包，不让用户另行安装 DSH 或插件。

## 验收拒绝与失败修正

- 浮动上游、开发工具超出准入范围、上游工具不满足其契约、缺实际构建/发行工具版本记录、虚构 API、裸 DSH/在线安装插件冒充工作台、仅 Mock/浏览器通过：拒绝首任务验收，回到固定源码核对与真实桌面验证。
- 混用工作台和模板工程、预建全目录而无可运行切片、同 worktree 多 writer：先修正职责和写入边界，再继续。
- 用 TCP/路由可达冒充数据库/协同登录/GitLab 管理 API/业务成功、以 Linux 成功冒充 Windows、缺必要正负用例或证据：保持该门槛未通过，定位缺项并复验。
- 失败保存脱敏证据并修正对应实现或架构；不加兼容层、migration 或 fallback，不静默绕过门槛，不给未验证交付日期。

本页不预设运行命令：编码者从固定提交和实际工程建立并验证后，才能记录可用命令。G0 全部准出以 [03-里程碑](03-待实现功能总览.md) 为准。
