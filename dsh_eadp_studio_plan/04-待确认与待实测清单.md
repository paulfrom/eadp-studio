# 4. 待确认与待实测清单

> 拆分自《eadp项目工作台：产品定位、过程资产与实施方案》；目录导航与原章节编号索引见 [README.md](README.md)。

以下分别列出已确定的产品约束及尚需补齐的实施证据；已确定的流程不再作为待选择项。

已确定的主流程：工作空间新建或 Git 地址获取项目；固定 `场景/`、`需求/`、`原型代码/` 三目录，一场景一 MD；明确用户自然语言确认与按钮共用 Host 入口。场景/需求确认均先推送固定 MD 到 Git，业务 API 只收 SHA-256 内容哈希、固定 Git 引用与控制元数据，不接受客户端上传正文；后端可按操作者既有 Git 读取权限临时读取固定 MD 校验，且不保存正文。场景确认后默认拆分本地候选并显示标题，选中后才预留正式需求 ID 和设计占用；需求确认后默认在门禁通过时编码。原型菜单提供 AI、源文件及运行预览，需求冲突需反向修订并重新确认。原型最终确认明确一个需求，完整相关代码/文档集成完成后固定基线，Host 后台生成可交付清单，无二次基线审批，清单失败独立重试。部署只使用项目当前已确认基线，到项目唯一目标；阶段 MD 提交不能冒充原型基线。上述均需实施验收，不重新讨论是否支持草稿部署或仅在本机保存已确认正文。

已确定的资产主线：场景/需求材料经必需检查、固定正文推送 Git 和后端阶段确认即可独立沉淀，不依赖原型完成；原型代码仍须集成及后端完成并固定原型基线。首期按完整场景包或完整需求包显式复用固定版本，不做规则、字段或代码片段级提取复用，不继承来源确认或完成状态。新增场景/需求明确记录业务分类和状态，客户端显示可复用资格及原因；客户端操作影响资格，后端与 Git 配合核验，客户端不能自行授予或绕过资格。

材料检查通过、固定正文推送 Git 且后端接受确认时同时自动授予复用资格，无二次资格按钮或审批；确认与资格分别记录，重复确认事件不得恢复后续已停用资格。所有具有该资产编辑权限的成员均可停用或恢复，后端按既有可信身份及该资产编辑权限受理，记录操作者、原因和时间，不以 Git 凭据代替授权；恢复不重做确认或基线。

### 产品与协同契约待确认

分类方向已确认按业务领域（如采购、库存、财务），不是按流程/规则/功能/异常等材料性质组织。所有具有项目编辑权限的成员均可维护项目分类词表，新增场景/需求选择已有项目业务分类；编辑既有分类保留固定材料历史分类及 ID，不自动改写历史正文。实际词表值与实现编码属于 G0 输入与验证，不扩为企业分类库。新草稿不可复用，编辑新草稿不暂停旧固定版本已有资格；显式停用经后端接受后生效并阻止新的采用，受理前不可冒称已生效。历史固定版本与已复制且独立维护的目标保留来源，不自动撤销。

在途采用规则已确认：浏览或选中不算采用，以后端接受采用记录为界；停用生效时尚未接受的采用阻止，已接受的采用保留固定来源继续，采用受理不绕过来源 Git 读取授权。采用受理不算复用成功；目标通过自身检查、确认并被后端接受后记录目标最终固定版本及来源，失败或取消不计成功。

材料准入与保留规则已确认：核心业务规则、验收条件明确才可确认并自动取得复用资格，核心缺失保留草稿；其他待澄清可保留但必须展示限制及不适用范围，不由 AI 编造补齐，沿用原有确认检查，无二次审批。正式确认材料、Git 可达固定引用、固定版本、来源记录及关联后端元数据、受理事件和来源证据长期保留，停用不删除；临时构建、缓存与任务现场单独清理，保护未提交、未推送成果和在途任务唯一现场，不新增备份平台。具体检查编码及清理执行通过 G0 验证，不再作为产品规则待选项。

- **已明确的协同约束与待实测项**：持久占用无超时释放，完成/作者取消/后端管理员手动释放；管理员释放原子中止任务和解除冻结，不同占用人及旧占用 ID 请求拒绝；每需求独立 worktree，设计时登记前置而生产认领时检查其完成；确认后自动继续合并，两次占用校验、精确候选检查、认可集成头及孤立操作阻断均已确定。仍需实测既有认证/后端管理员授权、框架/存储、API 编码、Git 条件更新与竞态核对；这些是实现验证，不重新引入自动到期占用。
- **项目资产契约与核心职责**：三业务目录及一场景一 MD 已确定；后端可按操作者既有 Git 读取授权临时读取固定 MD，在内存中核验实际哈希与控制元数据，正文不写入数据库、日志或文件缓存。此边界已确认，见 [临时 Git 正文校验决策](../docs/adr/0002-backend-transient-git-validation.md)。稳定项目/资产 ID、目录内命名及清单字段、结构化元数据解析、读取授权及失败阻断、正文不落盘/不进日志、真实用户确认入口、关系检查与模板执行仍须 G0 验证；不再将仅比较客户端自报哈希当作验证方案，不将仓库/会话/发布标识当作项目资产身份。
- **业务分类、状态与复用资格**：分类维护权、采用受理边界、复用成功条件及资格规则均已确定，不再列作待选项。G0 提供实际项目词表并验证分类/状态编码、原因表达和过期状态处理；实测项目编辑成员维护分类、新增选择已有分类、历史分类及 ID 不改写，确认受理同时授资格且无二次操作、重复确认不恢复后续停用、资产编辑成员停用/恢复与操作审计、恢复不重做确认/基线、停用受理前不显示生效、采用未接受阻止/已接受继续及失败取消不计成功。分类/状态在固定材料、后端和客户端之间一致，旧状态、本地修改或仅有 Git 凭据不能绕过核验，采用受理不能代替来源 Git 读取授权。
- **非研发使用与交接标准**：已明确直接使用者基本非研发、研发开发在外，核心业务规则/验收条件明确才确认、其他待澄清展示限制及不适用范围；G0 以真实材料验证必要内容检查、待澄清呈现、交接清单完整性、版本不匹配提示与澄清反馈。仍需落实实际试点人群、研发接收人员与既有权限，测量独立完成率/澄清轮次/信息缺口/定位耗时的现状基线后确认目标。沿用既有受信身份，新增后端承担已明确的进度、独占协同及必要分类/状态/复用资格控制元数据，与 Git 固定材料配合，不接收正文或扩为独立交接网站。
- **提交确认、基线与复用规则**：材料阶段确认独立沉淀、完整场景包/需求包显式复用、原型完成自动固定基线及后台清单已明确。用户已确定可选评审采用AI辅助评审，由作者自行确认；直接确认与AI辅助评审后确认均走同一可信确认和自动集成，不引入他人审批或独立业务评审者角色。AI依据固定候选和需求/验收条件提出问题与建议，作者处理后确认；修订后重检、更新依据并重新确认，不能套用旧报告或以AI结论代替作者确认及硬门禁。AI过程留本地，最终记录确认方式、固定引用及必要作者处置依据，不上传评审全文或冒称交叉评审通过。具体界面与合法/拒绝样例由 G0 验证，见 [M2-1](M2-1-确认后自动集成与冲突处理.md)。基线/标签权限与固定资料可读、完整包清单字段和检查编码由 G0 样例验证，上游待复核按既有固定关系规则执行。正式材料及关联证据长期保留，临时现场按保护规则单独清理；本地本人当前预览和远程单当前站点不提供历史切换。
- **后续概要/详细设计**：纳入优先级、源格式与成熟工具、输入依据关系、人工与 Agent 职责、校验及直接提交/评审规则（不默认强制交叉评审）、展示/交付方式、信息权限和独立准入样例；当前不开发工具，不承诺范围或日期。
