## 当前 GitLab 接入（2026-10-15 决策）

当前业务托管仍使用 GitLab 实例 `http://rddgit.changhong.com`，后端通过 `GITLAB_URL` 与显式 `GITLAB_ALLOW_HTTP=true` 允许已选择测试入口；不因 HTTP 探测擅自改变安全连接策略。工作台只登录协同后端，不直接以 GitLab OAuth/OIDC 登录；旧 OAuth/PKCE/loopback 专用源码与 2026-10-14 匿名探测记录保存于 [gitlab/legacy-oauth](../gitlab/legacy-oauth/README.md)。GitLab 管理 API 保持当前在用；归档不是暂缓整个 GitLab，也不是兼容或 fallback。候选 GitHub Device Flow 不进入当前运行路径。

默认预置测试管理员 `studioAdmin`（显示名“测试管理员”、邮箱 `songlin.liu@changhong.com`、默认密码 `admin@123`、协同 ID `1`）。账号资料邮箱与 GitLab API 返回的 `gitlabEmail` 是不同字段；后端绑定仍须按既有 GitLab 数字用户验证逻辑执行，不因账号邮箱字段而推定远端身份。默认 opaque 会话 8 小时，由后端保存哈希，登出撤销；Host 只配置 `collaborationUrl`，使用 `collaboration-session` 安全存储保存会话 token/expiresAt。默认账号只支持单账号测试，不冒称多人实名或管理员分权已验收。

`SEI_GITLAB_TOKEN` 仅由后端管理端配置；管理端可提供该凭据，实际可用性待后端运行配置验证，当前执行进程未继承它不等于凭据不存在。该 token 用于受控管理 API，不发送桌面、client、Agent、日志或业务数据库；桌面 Git 使用自己机器的用户凭据，不把协同 token 或管理 token 注入 Git。后端先按绑定用户的有效直接/继承成员、active 状态与到期验权，再进行仓库读取/管理，不采用管理 token 可见范围扩张目录或群组。

`GET /v1/namespaces` 只返回本人可建仓群组。读取项目至少 Reporter（20），编辑至少 Developer（30）；群组 `project_creation_level` 为 developer 时要求至少 30、maintainer 时至少 40，未知策略阻断。公开可读不等于工作台成员授权，协同管理员也不豁免 GitLab 成员权限；发布另按 `STUDIO_PUBLISHER_USER_IDS` 的协同用户 ID 独立授权。既有 GitLab 实例的具体版本、继承成员响应、状态/到期与建仓策略都须实际验证，不用最新官方文档替代企业实例证据。

## 新建、初始化与恢复

用户填写 name/path、选择后端返回的群组；`POST /v1/projects` 只接受 `{name,namespaceId,path,idempotencyKey}`。后端重核验群组权限，创建 private 空库，不初始化 README、不在空库创建时传 default_branch；为现有绑定创建者分配 Maintainer（40），登记业务项目和 pending 状态。返回 `ProjectView` 的 `namespaceId`、`namespacePath`、`initializationStatus`、canonical remote 与稳定分支 main；pending 时 `recognizedHead` 为 null。

Host 本机 Git init，创建 `场景/`、`需求/`、`原型代码/`，复制指定模板并写 `project.assets.json`，以本机可信 system/global Git credential helper 完成 root 首提交与 push main。只接受与后端 GitLab origin 一致的 canonical HTTP(S) .git URL，拒绝仓库本地 helper/hooks/URL 改写等配置，禁用 hooks；不注入 HTTP 授权头或 askpass，不改走 SSH fallback。

Host 调用 `POST /v1/projects/:id/initialize` 的 `{commitSha,idempotencyKey}`；后端读取真实远端 main 头，核验 root 首提交、manifest 的 schemaVersion/projectId/gitlabProjectId/repositoryUrl/stableBranch/directories 和固定三目录 tree 后，才原子置 ready 并登记认可初始头。ready 前不得业务占用、材料确认、完成基线或发布。旧客户端自报 GitLab ID/初始头的 RegisterProject 路径删除，不保留兼容。

建仓、成员分配、本机初始化/推送与数据库不是同一事务。使用稳定项目/操作记录和幂等键分段恢复，响应丢失先查询；创建相同输入恢复同一项目，输入变化拒绝，不重复建仓、不接管 path 冲突的未知仓库、不覆盖或删除本机已有现场。初始化核验失败保留 pending 并显示实际原因，不能因 push 成功直接宣布 ready。

## 固定内容与联合验收

后端先按协同操作者绑定的 GitLab 有效成员权限验权，再以管理 API 临时读取登记仓库、固定 commit SHA 与核验后的相对路径对应 MD；内存复算实际 SHA-256 与结构化元数据。正文不进入数据库、日志、落盘缓存或错误响应，业务 API 拒绝上传正文。读取/解析在短事务外，事务内重核验占用、revision 及业务条件；读失败、无权限、哈希/字段不一致或未知均阻断，不借管理 token 扩大读取，见 [ADR 0002](../docs/adr/0002-backend-transient-git-validation.md) 与 [身份/建仓 ADR](../docs/adr/0003-studio-auth-and-project-provisioning.md)。

G0-4 与 G0-6 联合验证以下真实路径，并与隔离数据库/合成检查分开记证据：

- 协同登录、密码拒绝、过期/注销、唯一既有账号解析和持久绑定、绑定失效；目录与群组严格按绑定成员权限过滤，管理员/管理 token 不扩大权限。
- private 空库创建、现有创建者分配、群组策略拒绝、用户本机首次 push、固定 root commit/manifest/三目录核验；重复请求/成员分配或响应丢失可恢复，pending 门禁与非法自报仓库 ID 拒绝。
- 固定 MD 的真实授权读取、伪造关系/分类/来源、错误哈希、权限撤销、不可读引用与正文防泄漏；Git 条件更新、精确候选、分支规则拒绝、管理员释放/在途 Git 竞态、孤立操作阻断与核对纠正。

旧 OAuth 匿名登录页及授权路由可达仅是历史探测，不能证明新的协同登录或管理 API 已通过。默认单账号不替代双作者隔离；Windows 本机 helper、Host 会话安全存储及真实 GitLab 均须独立实测。本地预览是 G0 的发布范围终点；单站点远程发布作为独立功能 M2-2 完成，不是 G0 门槛。当前实施结果见 [协同登录与项目交接](../docs/development/handoffs/studio-auth-projects.md)，不据文档或代码检查宣布 G0 通过。

## 单站点发布独立功能（M2-2，不属于 G0）

场景及需求 MD 确认先推送固定 Git 版本，再提交内容哈希与引用；推送失败或引用不可读不能显示已确认，响应丢失查询原操作。阶段 MD 可推进认可头，但不生成原型完成基线。部署只接受 ready 项目当前已确认 baseline ID、固定代码 SHA 和后端完成依据，拒绝未确认 worktree、候选分支和仅确认 MD 的提交。MD SHA-256、Git SHA 与构建产物校验值分别记录，不能互相替代。

发布继续使用 Host 独立授权的专用操作与项目唯一当前静态站点，不依赖 GitLab CI/Pages 或 GitHub Actions/Pages。独立发布/撤回权限、固定 SSH 主机指纹、访问策略、跨机器原子替换及故障撤回门槛属于 M2-2 功能验收。

官方模式参考为 [GitLab Users](https://docs.gitlab.com/api/users/)、[Groups](https://docs.gitlab.com/api/groups/)、[Members](https://docs.gitlab.com/api/members/) 与 [Projects](https://docs.gitlab.com/api/projects/) API；它们不证明所选企业版本已实现或通过本项目调用。
