2026-10-13 增补：产品最终形态固化为 DSH 桌面客户端上的工作台 Studio——打开即五阶段主界面，协同后端为企业集中部署的固定服务；产品形态决策与主界面结构见 [05-产品形态与主界面.md](05-产品形态与主界面.md)。

2026-10-14 桌面交付修订：面向用户交付一个可安装的 eadp 项目工作台，基于官方 DSH 桌面工程构建，内置并默认启用工作台插件、指定模板和必要工具链。用户无需先下载 DSH 再安装插件；Linux 开发、Windows 原生打包签名与单包安装验收，产品统一版本和更新。发行工程见 06 §6.3.1，交付与测试见 07。

2026-10-14 资产主线确认：项目资产沉淀与复用是产品主线；场景/需求材料经必需检查及 Git/后端阶段确认即可独立沉淀，原型代码仍须完成原型基线。首期按完整场景包或完整需求包显式复用固定版本，采用后调整重验，不继承来源确认或完成状态。新增场景/需求明确记录业务分类和状态，客户端显示可复用资格及原因，资格由后端与 Git 配合核验；确认同时自动授资格、停用/恢复及在途采用边界已确定；资产编辑成员可停用/恢复，项目编辑成员维护分类词表，实际词表值及编码由 G0 验证。保留五阶段，不新增阶段或审批。

本次同步主流程：工作空间新建/Git 获取项目 → `场景/`、`需求/`、`原型代码/` → 场景 MD 确认推送 Git 并登记哈希 → 默认拆需求并显示候选标题 → 选中需求交互确认、推送并登记哈希 → 门禁通过后默认编码 → 原型菜单 AI/源文件/预览及反向需求修订 → 明确一个需求完成并集成完整相关代码文档 → 自动基线与 Host 后台可交付清单 → 仅当前已确认基线部署至唯一远端。业务 API 不接受客户端上传正文，后端按操作者 Git 权限临时读取固定 MD 校验且不保存正文；清单失败独立重试，基线页面无二次审批。以上为产品决策，接口与运行证据仍以 G0/M1/M2/M3 实测为准。

2026-10-14 评审方式已确定：作者直接确认，或经 AI 辅助评审后自行确认，均走同一可信作者确认与自动集成，不要求另一成员审批；AI 结果不代替工程检查和后端门禁，报告及过程留本地，Git/后端仅按既有边界记录最终确认方式、固定引用和必要作者处置依据。

2026-10-14 正文边界已明确：Git 保存固定正文，协同后端可按操作者既有读取权限临时读取并在内存校验实际哈希与元数据；正文不写入数据库、日志、文件缓存或错误响应，业务 API 仍拒绝正文上传。依据见 [临时 Git 正文校验决策](../docs/adr/0002-backend-transient-git-validation.md)。

2026-10-15 身份与建仓修订：当前保持 GitLab，工作台只登录协同后端，独立协同用户绑定既有 GitLab 数字账号；管理 token 仅后端配置，项目目录/群组不借管理权限扩张。后端先建 private 空库并置 pending，Host 本机用户 Git 初始化推送，后端验证远端头/manifest/tree 后 ready。新契约见 [ADR 0003](../docs/adr/0003-studio-auth-and-project-provisioning.md)、[G0-4](G0-4-代码托管与单站点发布契约.md) 及 [本次交接](../docs/development/handoffs/studio-auth-projects.md)。旧 OAuth 专用实现仅存 [legacy-oauth](../gitlab/legacy-oauth/README.md)，不进入当前运行路径；旧验证不改写为新流程已通过。

2026-10-15 范围修订：G0-1、G0-2 桌面打包已完成；当前阶段不要求签名或升级验收。G0 总体验收以本地预览为止，不包含远程站点发布；单站发布作为独立功能 M2-2 完成。
