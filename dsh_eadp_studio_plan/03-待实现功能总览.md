### 3.2 新建、打开与恢复项目的后台步骤

用户先在工作空间新建项目，或输入 Git 地址获取已有项目；客户端登录企业集中部署的协同后端固定服务（登录方式见 04 册）。用户主要操作场景、需求与原型，工程步骤由 Host 自动完成，配置缺失由维护者处理。

业务 API 只接收固定 Git 引用、哈希和控制元数据，不接受客户端上传正文；后端按当前操作者既有 Git 读取授权临时读取固定 MD，独立核验实际字节及实体、分类、来源、场景和前置关系，正文仅在内存中使用且不保存。读取无权限、引用不可读、哈希或字段不一致及结果未知均阻断受理；相关正负用例及正文不进数据库/日志/文件缓存/错误响应，按 [G0-6](G0-6-协同后端与持久占用.md) 和 [正文校验决策](../docs/adr/0002-backend-transient-git-validation.md) 验证。

1. 通过当前代码托管集成连接用户既有 GitLab 账号，按入口核查权限：新建检查目标 group 建仓权限与仓库路径唯一性，Git 获取检查目标仓库及后续所需分支读写权限；同时检查工具链与模板契约/版本/校验值，生成一次操作标识。权限不足返回真实错误，不进入开户流程。
2. 新建项目建立稳定 project ID 与项目清单，默认创建 `场景/`、`需求/`、`原型代码/` 三个业务目录；从随包指定模板复制原型工程，验证工程及 `AGENT.md` 完整。创建获授权远程仓库、推送初始提交，关联无凭证 remote/provider/仓库标识和稳定分支；后端按可信项目创建权限核验可读取的初始 SHA 并登记为认可初始集成头，之后任务以此为基础。初始化未完成时不允许任务认领或发布，不调用通用脚手架。
3. 输入 Git 地址时 clone 到受管理工作空间，验证项目身份、三目录及资产清单、源文件路径和原型模板标记。已有项目尚无原型工程时登记首个原型资产并复制模板，不重复建仓；已有原型工程时在该资产中增量修订，多页面仍属同一发布对象，本期不创建第二个原型工程；输入地址不代表支持任意工程转换。
4. 在场景菜单新建场景即创建一个 MD 文件，同时明确记录业务分类与状态；新建需求同样记录。明确的用户自然语言确认与确认按钮进入同一 Host 入口：冻结本次文件字节，计算 SHA-256 内容哈希，提交并推送该 MD 至 Git，再向后端上报哈希、固定 Git 引用及必要控制元数据，不上传正文。必需检查通过且后端接受阶段确认后，材料即可独立沉淀并自动取得复用资格，无二次资格操作或审批；确认与资格分别记录但同时受理，重复确认不恢复后续停用。可复用资格仍须按后端状态与 Git 固定材料核验，客户端显示不得代替该判断。后端接受后默认启动 Agent 拆分，展示本地候选需求标题及内容；同一确认事件重试复用任务，失败可继续，不重复生成一套需求。候选尚未确认，也不提前占用所有候选。
5. 用户选中一个候选后，预留正式需求 ID 并取得设计占用，与 AI 完善需求 MD；确认同样先推送固定 MD，再由后端接受哈希与引用。后端接受后默认尝试原型生产，按既有契约原子核验占用、场景冻结和全部前置完成依据；未满足时展示阻断原因，不调用编码 Agent。通过后从认可基础创建该需求独立 worktree/分支，绑定 project/requirement/asset、确认输入、前置完成事件及占用 ID；按模板冻结安装及检查，绑定官方 session 和本地单写入锁，经已验证入口加载 `AGENT.md` 后自动编码。依赖缓存仅按模板工具已验证能力复用。
6. 原型菜单提供参考 bolt.new 的 AI 对话、源文件查看和运行预览。完成 Mock 初始化及 ready 检查后仅展示本人当前需求 worktree 的 loopback 预览，不提供历史切换，也不随他人合入自动更新工作基础。用户可直接反馈修改；若与已确认需求冲突，生成需求修订供用户确认，推送新 MD 并登记新哈希，保留代码现场，按既有门禁重新绑定任务后继续。
7. 生成/修改后执行模板工程、类型（适用时）、静态构建及浏览器验证。作者在原型菜单确认并明确或选择一个需求完成，Host 提交本任务完整相关代码和文档，基于认可集成头生成项目集成快照，禁止混入其他需求未完成草稿；按作者直接确认或 AI 辅助评审后作者确认路径自动进入精确候选检查、条件合并及后端完成确认，不另设手动合并。
8. Git 与后端完成均成功后固定基线；Host 后台任务按该基线自动生成可交付清单。基线页面展示结果，不增加第二次审批；清单失败单独重试，不重做需求完成。原型菜单提供“部署到远端”，只将项目当前已确认基线的固定代码版本部署到项目唯一配置目标，不部署草稿或仅完成 MD 阶段确认的提交。

打开既有项目时，以项目身份、仓库关联和资产清单识别，通过代码托管边界校验真实仓库/分支权限；开始原型任务时再验证对应目录的模板标记与 `AGENT.md`，不凭账号存在或仓库名称判断合规。不导入、转换或自动升级契约之外的工程。
恢复前先查询需求 revision、前置条件、当前 occupation ID/代次及 owner/task/client、集成操作和认可集成头；占用被撤销/替换或输入变化时，不沿用旧权限或抢占。再核对本人 worktree、分支、SHA、未提交改动及任务记录，不一致时展示原因，不重置文件，也不自动把远端最新成果覆盖到本地。
网络重试先查询操作状态：代码托管边界核查仓库、任务分支/可选 MR 和集成操作；协同后端核查当前占用、完成事件及认可集成头；发布核查当前部署操作和产物标识，防止重复建仓、重复合并、重复评审或重复发布。
外部状态未知时显示“待确认”，待重查后继续；重试次数和超时有上限，不以无限重试掩盖权限或配置错误。

### 3.8 质量、性能与成本基线

协同质量单独统计认领/释放/提交受理/最终完成时延、占用冲突、管理员释放及旧请求拒绝、前置阻断、待同步时长和幂等结果。占用不因断网自动释放、两次占用人校验、前置未完不得生产、精确候选检查、场景原子联动及孤立合并阻断是功能准出，不用平均时延掩盖错误。容量与性能目标由 G0 实测确定，不虚构并发人数。
产品可用性和沟通效果优先统计：非研发独立完成率、理解/操作难点、维护者介入、澄清轮次、交接信息缺口及研发定位耗时。对同类需求先记录当前沟通方式的基线，记录试点样本和条件后才判断改善，不能虚构降低比例；收到交接不计为开发完成。
公共资产质量单独统计来源完整率、需求/前置/反馈/确认可追溯率、关系检查、固定版本读取、待复核处理和显式复用记录。材料沉淀须经过必需检查、固定正文推送和后端阶段确认；原型基线须另经过自动集成及后端完成确认。新增场景/需求的业务分类和明确状态须与固定 Git 材料、后端记录及客户端显示一致，可复用资格和原因可核验，客户端不能绕过后端资格。复用按完整场景包或需求包记录来源、调整及目标当前任务检查结果，不以文件数或模型输出字数衡量价值。目标值由 G0 测量后确认，不以恢复历史预览作为准出。

材料准入与保留必需验证：核心业务规则及验收条件明确才通过原有确认检查，核心缺失保留草稿且不授复用资格；其他待澄清可以保留但须展示限制与不适用范围，不能由 AI 编造补齐，不增二次审批。正式确认材料、Git 可达固定引用、固定版本、来源记录及关联后端元数据/受理事件/来源证据长期保留，停用不删除；临时构建、缓存和任务现场单独清理，未提交、未推送成果及在途任务唯一现场保护检查失败时阻止清理，不建设备份平台。

业务分类按业务领域组织。资格动作必需验证：材料经检查、Git 推送且后端接受确认时自动授资格，确认与资格分别记录但同时受理，无二次资格按钮或审批；原型代码另须完成基线；重复确认事件不恢复后续已停用资格；新草稿拒绝采用；编辑新草稿不暂停旧固定版本已有资格；显式停用受理前不显示已生效，后端接受后阻止新的采用；所有具有该资产编辑权限的成员均可停用/恢复，后端核验既有可信身份与该资产编辑权限并记录操作者、原因和时间，不以 Git 凭据代替授权，恢复不重做确认或基线；历史固定版本与已复制且独立维护的目标保留来源、不自动撤销。采用以后端接受记录为界，浏览或选中不算采用，停用时未接受的采用阻止、已接受的保留固定来源继续，不绕过来源 Git 读取授权；目标自身检查/确认由后端接受后登记最终固定版本及来源才计复用成功，失败或取消不计成功。所有项目编辑成员可维护分类词表，新场景/需求选择已有分类；编辑既有分类保留固定材料历史分类及 ID，不改历史正文。实际词表值和编码作为 G0 输入/验证。
