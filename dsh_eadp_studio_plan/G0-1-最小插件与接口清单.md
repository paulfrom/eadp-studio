## 桌面发行门槛（2026-10-14 交付物纠正）

用户交付物是本产品可安装的 Windows 桌面工作台。最小插件仅是内部实现和构建验证件，不要求用户先下载 DSH 或自行安装插件。固定官方 DSH 源码与发行基线，复用其 Electron/electron-builder 管线，内置并默认启用 Studio 插件、指定模板与所需运行时；不新造 Electron 壳、独立 launcher 或通用更新器。

以下内容为桌面交付背景与长期发行要求；本阶段 G0 验收不要求签名、升级或卸载，按本地预览完成工作台验证：

- 在未安装 DSH、系统 Node/pnpm/Git 或模板运行时的 Windows 原生干净机，仅安装本产品签名安装包，由快捷方式打开即五阶段 Studio；不进入在线 add 插件流程，不要求手工配置模板运行时。
- 在已有官方 DSH 的 Windows 机器验证共存：工作台使用独立应用标识、安装目录、数据 profile、快捷方式和更新来源；安装、启动、更新及卸载工作台均不改动原有 DSH 的安装、配置/profile、命令注册或协议关联，两个产品互不覆盖。
- 记录 DSH 基线/提交、产品版本、插件/模板/运行时版本、完整 production 依赖树、安装包签名与校验值；Linux 通用资产与 Windows 原生包追溯同一固定源码和锁文件。
- 使用统一产品版本与产品更新渠道，复用官方整单元更新模式，防止上游 DSH 更新覆盖内置插件组合；验证版本配套，不开放未经验证的自动更新，不提供用户单独更新内置插件路线。
- 升级保留业务仓库、确认资产、用户配置与恢复信息；关闭或升级不释放后端持久占用，恢复后继续绑定当前有效占用；卸载保留用户业务资产。应用安装目录与用户资产目录分别管理，不建设旧版兼容或迁移机制。

官方成熟模式依据为 [DSH desktop README](https://github.com/deepseek-ai/deepseek-harness/blob/master/apps/desktop/README.md) 的 Electron 构建、随包 Node/pnpm、签名 Windows 安装与整单元更新。上游 master 文档不能证明目标固定基线可用；Git、实际模板运行时与全部执行入口另由 G0-2 实测。具体环境与证据要求见 [07-开发与测试环境.md](07-开发与测试环境.md)。

## 新增产品能力（2026-10-13 产品决策）

- **主界面满窗形态与模型配置**：本产品安装后打开即五阶段 Studio（全局 `main` 面板满窗为主界面）；模型经宿主会话配置，不另建接入层；验证定制发行固定 DSH 基线的面板能力边界。详见 [05-产品形态与主界面.md](05-产品形态与主界面.md)。
- **主流程入口验证**：工作空间新建与 Git 地址获取项目、场景/需求/原型菜单及固定三目录；明确用户自然语言确认与按钮调用同一 Host 确认入口，验证文件/版本绑定及重复点击/重复消息幂等。Agent 生成的文字不能自授确认；普通聊天不能误触完成。验证后端接受场景后默认拆分、接受需求后默认申请编码，以及原型菜单中的 AI、源文件查看、运行预览和部署入口。
- **确认与后端内容校验**：Host 仅上报固定 Git 引用、哈希及控制元数据，业务 API 拒绝上传正文；后端按操作者有效 Git 读取授权临时校验固定 MD，不持久保存正文。联合 G0-4/6 验证实际读取、错误哈希、伪造元数据、权限不足及引用不可读均可靠处理，失败或未知不得继续拆分/编码；正文不进入后端日志、落盘缓存或错误响应。该校验不替代真实用户确认及 DSH 执行审批，见 [临时读取校验决策](../docs/adr/0002-backend-transient-git-validation.md)，当前仍待实测。
