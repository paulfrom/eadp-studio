# 7. Linux 开发与 Windows 桌面测试

> **G0 范围更新（2026-10-15）：G0-1、G0-2 桌面打包已完成；当前 G0 验收以本地预览为止，不要求签名或升级/卸载验收。单站远程发布作为独立功能 M2-2 完成。**

本项目在 Linux 开发，向用户交付一个可安装的 Windows 桌面工作台。固定官方 DSH 源码与发行基线，复用其 Electron 构建管线制作本产品定制发行；安装包内置并默认启用 Studio Host/client 插件、指定模板与所需运行时。用户安装本产品后即可进入五阶段 Studio，无需先安装 DSH、管理插件、安装系统 Node/pnpm/Git 或手工配置模板运行时。协同 API 独立部署。

代码采用 TypeScript + pnpm monorepo。Linux 构建与检查通用资产，Windows 在同一固定源码和锁文件上完成平台依赖准备、原生打包、签名及安装验收。插件包是内部构建件，不是用户交付物；不新造 Electron 壳、独立 launcher 或通用更新器。

本文固定开发、交付与验收边界，不代表相关工具、SDK 能力或 Windows 用例已经通过。仓库准备配置、模板快照、`scripts/check-repository.mjs` 和 `scripts/fetch-dsh.mjs` 已落地；其余业务与测试路径仍为规划。固定 DSH 归档已核验，完整解包受当前 Windows 符号链接权限阻塞，详见 [开发准备](../docs/development/setup.md)。实际 DSH 接口、桌面发行构建/安装及内置插件加载入口按目标固定基线的 G0-1 证据确定，本文不定义虚构宿主 API 或 CLI 命令。

## 7.3 从 Linux 源码到 Windows 安装包的交付路径

1. **开发与检查**：Linux 从固定源码版本安装工具工程依赖，按锁文件执行冻结安装，完成类型、边界、契约及适用业务规则检查；协同 API 使用真实目标数据库执行必要事务测试。
2. **构建内部资产**：按固定 DSH 基线已验证的插件构建入口生成 Host/client 和指定模板，记录源码 SHA 与校验值。内部插件资产不携带开发 `node_modules`、构建缓存、`.git`、凭证、私钥及本地敏感配置；Windows 所需平台资产在同一源码/锁文件上生成并记录，不声称 Linux 构建天然支持 Windows。
3. **Windows 原生打包与签名**：复用固定基线的 Electron/electron-builder 管线，组合宿主完整 production 依赖树、默认启用插件、模板、已验证的 Node/pnpm/Git 及模板运行时，生成签名安装包。发行清单记录每项版本、来源、许可、平台、校验值与实际路径。打包机可安装开发工具；这些工具不能成为用户机器前置条件。
4. **干净机首次安装与执行**：使用未安装 DSH、系统 Node/pnpm/Git 或模板运行时的 Windows 原生机器，仅安装本产品单一安装包。由快捷方式启动即进入五阶段 Studio，内置插件不经在线 add；完成模型/账号授权后创建三业务目录项目、打开获授权 Git 项目、认领独立需求 worktree，并验证官方会话、规则加载、检查、预览及取消/重启恢复。凭证由用户按业务授权提供，不复制打包机凭证。
5. **真实协同与发布验收**：两个客户端连接同一测试后端与 GitLab 测试仓库；验证并发、持久占用、精确集成、响应丢失恢复和固定基线发布。在实际静态站点检查 Mock、路由、资源、base path、协议与访问策略。
6. **升级、卸载与交付证据**：验证产品整套升级后业务仓库、确认资产、用户配置与在途占用可恢复，关闭/安装升级不释放后端持久占用；卸载不删除用户业务资产。保存可追溯且脱敏的环境清单、用例结果、安装/升级/卸载日志、录屏、签名与校验值。安装包通过相应 Windows 门槛后才标记可用，不以文档完成或 Linux 检查成功宣布交付成立。

产品使用统一版本与产品更新渠道，宿主、内置插件、模板和运行时作为经验证的同一发行组合更新。复用官方已有整单元更新机制并绑定本产品渠道，禁止上游 DSH 更新覆盖本产品组合；不提供用户分别更新内置插件的路线，不建立另一套通用更新器。版本配套与更新渠道必须在目标固定基线实测；未验证前不得开放自动更新。用户业务资产与安装目录分离，安装、升级及卸载不能把业务目录当作应用缓存清理；不为过时接口保留兼容路径或编写迁移机制。

除干净机外，另在已安装官方 DSH 的 Windows 机器验证共存。本产品使用独立应用标识、安装目录、数据 profile、快捷方式和更新来源；安装、启动、更新、卸载均不得改动原有 DSH 的安装文件、配置/profile、命令注册或协议关联。检查两者可独立启动及更新，避免仅在干净机通过而掩盖产品标识或数据目录冲突；该共存用例同属最终安装包门槛。

规划的辅助入口采用 Node 脚本，例如 `scripts/check-toolchain.mjs`、`scripts/check-boundaries.mjs`、`scripts/verify-desktop-artifact.mjs`。它们是项目内部检查设计，尚未创建，不替代官方桌面构建/安装契约，也不将任意命令包装成可受 Agent 调用的工具。

## 7.4 路径与内容字节

资产契约中的文件引用使用仓库相对路径；本机绝对路径只在 Host 文件访问边界产生，不进入交付清单或静态页面。Host 在访问前解析真实目标并核验仍处于允许的项目/worktree 根内，拒绝绝对输入、`..` 逃逸以及链接或 Windows junction 导致的越界。远端部署目录使用其独立的已验证契约，不将 Windows 驱动器路径传给远端。

文件名使用稳定 ID；新建时检查 Windows 大小写不敏感冲突、保留名称和不允许字符。Windows 原生测试必须覆盖中文目录、空格、不同驱动器与工作区路径；长路径能力按实际 OS、Git、DSH 与模板工具共同验证，不承诺所有路径可用。路径处理使用标准路径库和结构化参数，不以字符串替换斜杠代替根目录校验。

MD 确认采用明确的 UTF-8、无 BOM、LF 保存契约。Host 先完成保存，再对实际文件字节计算 SHA-256；确认快照、提交源及上报字段绑定同一份字节。推送后按固定 Git SHA 和路径读取原始 blob 复算，字节不一致则阻断确认及后续 Agent 任务。不得在 hash 后再转换换行、Unicode 内容或编码，也不得读取另一个当前工作区文件替代固定 blob。

业务 API 拒绝客户端上传正文，后端数据库无正文列。后端按真实操作者有效 Git 读取授权，从登记仓库、固定 commit SHA 和经核验的相对路径临时读取 MD，在内存核验实际 SHA-256 及实体、分类、来源、场景和前置关系与上报字段一致；不得以无授权通用服务凭证扩大读取范围。Git 读取及解析在短数据库事务外完成，事务内重核验占用、revision 等条件；读取失败、无权限、哈希或字段不一致及结果未知均阻断，不回退信任客户端声明。正文不得进入数据库、日志、落盘缓存或错误响应，见 [临时读取校验决策](../docs/adr/0002-backend-transient-git-validation.md)。实际字段解析、超时及大小限制由 G0 验证，当前未实现或验收。

工具仓库与业务资产仓库分别提交明确的 `.gitattributes` 文本/二进制规则；受控 MD 和清单使用 LF，模板文件规则按其实际内容制定。不能依赖开发机的 `core.autocrlf` 设置保证内容一致。Git 属性只稳定检出/入库行为，不能代替 Host 的实际字节与固定引用核验。研发仓库已创建根属性文件，导入模板的文本采用 UTF-8 无 BOM/LF、PNG/ICO 保留二进制原字节；业务资产仓库规则及 Host 固定字节校验仍待实施。

成熟依据：[Git gitattributes 关于 text/eol 的官方说明](https://git-scm.com/docs/gitattributes)。产品依据为 [02-项目架构.md](02-项目架构.md) §2.1.1、§2.2.3、§2.7.7。

## 7.5 命令、进程与凭证

Host 执行入口接收已核准的操作类型、工具身份、参数数组、工作目录、环境变量白名单及任务 ID。模板的安装、检查、预览和构建只能调用已验证契约；GitLab/Git 与发布各用专用操作。用户内容、MD 文本或 Agent 输出不能变成 shell 命令、可执行文件路径或环境变量。client 和纯领域包不能启动 shell、读取凭证或执行 Git。

Git 使用后端返回的 canonical HTTP(S) remote，用户凭据来自本机可信 system/global credential helper；只有专用 Git 用户凭据操作继承必要 HOME/USERPROFILE 等环境，不给普通模板/Agent 工具继承。拒绝仓库本地 credential/helper/hooks、URL 改写、filter/include 等配置并禁用 hooks，不注入后端管理 token、协同 token、HTTP 授权头或 askpass，也不转 SSH 作为 fallback。需在 Windows 实测 helper 可用和凭据隔离，协同登录成功不能代替首次 push 成功。

Windows 的 `.cmd`/`.bat` 启动行为与 Linux 可执行文件不同。Node 官方说明此类脚本不能直接通过 `execFile()` 执行；实现必须在 G0 固定目标工具的实际启动形式。可执行程序使用参数数组直接启动；确需命令解释器的工具仅由专用平台边界按已验证的固定调用形式执行，并对引用、特殊字符及注入用例验证。不能开放任意 shell 字符串，也不能在调用失败后自动改用另一启动方式。本文不预设 DSH 已暴露 Node `child_process` 能力。

成熟依据：[Node.js child_process 关于 Windows .bat/.cmd 的官方说明](https://nodejs.org/api/child_process.html#spawning-bat-and-cmd-files-on-windows)。具体 Host 执行入口仍以 G0-1 的目标宿主契约为准。

进程管理仅针对插件拥有的任务与模板预览，不建设通用进程守护器。启动记录绑定 task、worktree、工具版本、端口和 ready 结果；仅监听 loopback，未满足 ready 契约不能显示「本地原型」。最小化窗口不终止任务。取消、关闭及重启时核对任务和进程状态，完整清理所属进程树，不凭旧 PID 或端口被占用判定原进程存在。Windows 的 spawn、stdio pipe、取消中断及子孙进程退出必须原生验证；不照搬 POSIX 信号语义。

桌面端凭证只由专用 Host 操作通过已验证安全设施取用。本机用户 Git 凭据、协同会话和发布凭证分别管理，后端 GitLab 管理 token 仅由后端取用；凭证不进入 client 状态、参数显示、普通日志、环境转储、提示词或静态产物。后端临时 Git 读取前按协同用户绑定的 GitLab 有效成员权限验证，不以管理 token 可见范围扩大授权。发布授权不能从 GitLab 项目角色推导，SSH Agent 可访问也不能被视为调用方隔离成立。

Windows ACL 和受限 webview 的现有资料不能证明完整执行隔离。保护须覆盖官方 Agent 的全部文件写入/shell 入口、安装脚本、构建脚本及生成代码执行，并验证普通 Agent 无法修改模板规则/依赖/锁文件/构建配置、访问不允许的目标或使用发布凭证。专用操作内部检查不能弥补其他入口仍可绕过的权限。拦截必须在执行前发生；未通过时阻断相关能力，不添加 fallback，不称为安全沙箱。

采用 MSW 浏览器模式时，Windows 浏览器与远端站点必须验证安全上下文、Service Worker URL/scope、初始化等待及更新。HTTP 目标不能满足所选模板条件时阻断发布，由维护者提供并验证适合该目标的模板；不临时关闭 Mock 或增加透传。HTTPS 目标检查证书链与主机名，失败不降级；HTTP 目标不执行证书检查。

每项证据至少包含用例 ID、固定源码与产品桌面包/宿主/内置插件/模板/运行时版本、OS 与 CPU 架构、工具路径及版本、必要授权前提、实际步骤、预期与实际结果、日志/录屏引用、执行时间。未来单独执行发行完善时再记录签名/校验值、更新来源及用户资产/占用恢复结果。日志脱敏，保留失败现场和状态；未知、未执行与失败分别记录，不将未知归为成功。证据可以按 `evidence/g0/windows/<run-id>/` 组织，此目录亦为规划；完整会话、提示词和草稿仍仅留本地，不上传协同后端。

缺少独立复验时标记 `self_review`，与真实独立复验区分。报告分别列出 Linux 检查、Windows 原生宿主验证、真实协同验证及实际站点验证结果。只有本门槛对应的必要用例完成并保留证据后，才宣称该项能力成立。

## 7.7 实施顺序与来源

先完成 G0-1 的固定 DSH 基线、内置最小插件、桌面打包与接口取证，再完成 G0-2 的本地预览工具链、执行入口与进程树验证；同时用 G0-3 固定实际模板和规则加载契约。随后以真实双客户端验证协同与恢复，并以本地预览完成 G0 范围。单站点远程发布作为 M2-2 独立功能；签名、升级和卸载另行安排，不作为当前 G0 前置。

成熟构建依据：[DSH desktop README](https://github.com/deepseek-ai/deepseek-harness/blob/master/apps/desktop/README.md) 中的 Electron/electron-builder、完整 production 依赖树、随包 Node/pnpm、Windows 签名安装与整单元更新模式。该链接指向上游 master，只支持选用现有模式；目标固定基线的构建、品牌配置、内置插件、Git/模板运行时和产品更新渠道仍需 G0 实测，不能据此声称已实现或复刻其过时兼容路径。
