## 新增产品能力（2026-10-13 产品决策）

- **固定后端**：协同后端按企业集中部署固定服务交付，客户端连接固定服务地址（既有认证），不在用户侧部署。详见 [05-产品形态与主界面.md](05-产品形态与主界面.md)。
- **阶段确认与自动推进**：MD 正文推送 Git，业务 API 拒绝上传正文，后端仅持久登记 SHA-256 内容哈希、固定 Git 引用和控制元数据；按操作者有效 Git 读取授权临时读取固定 MD，验证实际字节与哈希/引用及上报字段一致，旧哈希不能确认修改后的文件。两个确认入口及网络重试共用幂等操作；场景接受事件仅驱动一项可恢复拆分任务，选中候选后才预留需求 ID/设计占用；需求确认后默认尝试编码，前置/占用/冻结未满足时可靠阻断。需求反向修订重新确认、绑定输入和检查门禁，原代码现场保留，旧输入任务不能完成；后端不持久保存正文或运行编码/清单生成。

## 临时读取校验门槛（2026-10-14 决策，2026-10-15 身份修订）

按 [临时读取校验决策](../docs/adr/0002-backend-transient-git-validation.md)，后端读取仅限登记仓库、固定 commit SHA 与经核验的仓库相对路径，先核验当前协同用户绑定的 GitLab 有效直接/继承成员、active 状态和到期，再以仅后端配置的管理 API 读取；不能采用管理 token 权限扩大用户读取范围，不再要求客户端 GitLab OAuth token。正文只在内存中核验实际 SHA-256 与结构化实体、分类、来源、场景及前置关系；数据库无正文列，正文不得进入日志、落盘缓存或错误响应。读失败、无权限、哈希或字段不一致及未知结果均阻断，不回退信任客户端自报哈希，不建立独立证明平台。

Git 读取和解析在短数据库事务外完成，事务内重核验占用、revision 与业务条件。G0 须执行真实授权读取成功、伪造元数据、错误哈希、读权限不足、固定引用不可读及正文不落盘/不进日志/不进错误响应的正负用例；该校验不替代真实用户确认或 DSH 执行审批。上述真实 GitLab 读取与防泄漏用例须在后端实际运行配置下执行；隔离数据库和合成响应检查的结果按本次交接单独记载，不计为企业实例或 Windows 通过。
