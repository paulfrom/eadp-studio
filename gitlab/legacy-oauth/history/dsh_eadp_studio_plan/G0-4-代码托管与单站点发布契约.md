## 已选实例与只读探测（2026-10-14）

用户已确认沿用模板 remote 所在 GitLab 实例 `http://rddgit.changhong.com`，并确认有维护者可办理工作台 OAuth 应用常规注册。实例选择及办理责任已明确，应用尚未注册，平台注册权限未实测；项目/组/分支权限、实际 GitLab 版本、PKCE、回调、scope、授权链及凭证安全保存均未实测。

| 实际输入或探测 | 结果 | 证据边界 |
| --- | --- | --- |
| HTTP `/users/sign_in` | 200 | 匿名登录入口可达 |
| HTTP `/api/v4/version` | 401 | 未取得实际 GitLab 版本 |
| 同 host HTTPS `/users/sign_in` | 200 | 默认 TLS 验证通过，未跳过证书验证 |
| HTTPS `/oauth/authorize` | 302 至 `/users/sign_in` | 仅证明授权路由可达，不证明客户端 ID、PKCE、scope、回调或完整授权链可用 |

本轮使用匿名、无 Cookie 的只读 HTTP 请求；OAuth 探测禁用自动跳转及 Cookie，未登录、注册应用或修改 GitLab。HTTPS 入口可达不代表模板 HTTP remote 已调整或 Git 传输已验证。

[GitLab 官方 OAuth 文档](https://docs.gitlab.com/api/oauth2/) 推荐 authorization code + PKCE，应用注册是前置条件，可作为 G0 验证方向；不能依据最新文档假设此企业实例支持，也不据此固定 scope 或替换现有 PAT 契约。G0 须在所选实例验证常规应用注册与实际授权链，仍遵守不升级、不装插件、不改服务端代码的约束；条件不能满足时，在设计时改选企业 OIDC，不实现运行时回退。

## 关联架构契约

补充验收：场景及需求 MD 阶段确认均先推送固定 Git 版本，再提交内容哈希与引用，推送失败或引用不可读时不能显示已确认；响应丢失查询原操作。阶段 MD 提交可推进认可头，但不生成原型完成基线。部署从原型菜单触发，仅接受项目当前已确认基线 ID 及其固定代码 SHA、后端完成依据，拒绝未确认 worktree、候选分支和仅确认 MD 的提交。MD 的 SHA-256 内容哈希、Git SHA 和构建产物校验值分别记录，不能互相替代。

后端按真实操作者有效 Git 读取授权，临时读取登记仓库、固定 commit SHA 与经核验相对路径的 MD，内存核验实际 SHA-256 及结构化字段与上报元数据一致，业务 API 仍拒绝上传正文且后端不持久保存正文。G0 与 G0-6 联合验证真实授权读取、读权限不足、引用不可读、哈希错误、伪造关系/分类/来源等元数据及正文不落盘/不进日志/错误响应；失败或未知阻断，不以无授权通用服务凭证扩大读取或回退信任客户端声明，见 [临时读取校验决策](../docs/adr/0002-backend-transient-git-validation.md)。上述用例尚未执行，既有匿名路由探测不证明该读取能力成立。
