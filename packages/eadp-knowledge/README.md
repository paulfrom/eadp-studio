# 知识库插件

目标与取舍见[本地知识库与需求引用方案（V0.3）](../../docs/design/local-knowledge/README.md)。本包当前实现方案的**阶段一：统一资料与导入**；阶段二（本机查找、自动参考、需求依据）与阶段三（向量混合）尚未实现，embedding 接口缺口登记在[固定宿主接口缺口](../../docs/blocked-upstream.md)。README 描述实现事实，不代表桌面验收或生产就绪。

## 用户能做什么

- 通过资料页或导入记录导入任意扩展名的本机文件。Host 先按内容保存原件与一条独立导入记录，再异步转换；可转换的文件成为可编辑文档，不可转换的进入“需要处理”，保留原件，可查看、重试或手工整理。
- 资料列表按分类、来源和关键词筛选；点击标题进入整页明细，正文占据主要阅读宽度，来源与原件单独页签。
- 文档打开后直接在排版结果上编辑：标题层级、段落、粗斜体、列表、引用、表格、代码块、分隔线、图片、撤销与中文输入法；保存后的阅读样式与编辑时一致，不出现源码与预览双栏。
- 内置知识只读，可复制为我的知识；内置与用户资料都能设置“参与需求沟通”，该偏好保存在用户资料清单中，不修改随包文件。
- 保存后的后台整理只在模型可用时补充标签；模型未配置、超时或返回无效都不会阻断正文保存，明细页如实显示“自动整理未完成”并提供重新整理入口。

## 存储与边界

用户资料位于 `resolveDshHome()/knowledge/`：

```text
manifest.json                       权威目录、资料元数据、内置自动参考偏好
cards/<documentId>/<bodyHash>.md    不可变正文
source-maps/<documentId>/<contentRevisionId>.json
assets/<assetHash>.<ext>            正文引用的图片，内容寻址
sources/<sourceHash>/payload        不可变原件
sources/<sourceHash>/metadata.json
imports/<importId>.json             独立导入记录（含失败原因与诊断）
```

- 正文、资源与来源映射先落盘，manifest 最后原子提交；每次保存按该资料的当前内容版本做条件写入，不受其它资料的编辑、导入或删除阻断。
- 正文文件、原件、来源映射与导入记录分别持久化；清单刷新或重启后导入记录仍在。启动只核对可判定的孤儿与临时文件，不删除未知文件。
- 原件、资源大小与批量数量有上限，命中时对每个文件如实说明；不按扩展名直接拒绝。
- 转换在独立 worker 线程内完成，Host 不加载解析器，也不在事件循环里做阻塞解析。

## 自动转换范围（阶段一实测范围）

文本与 Markdown、CSV/TSV、HTML、PDF（有文字层）、Word（.docx）、Excel（.xlsx）、PowerPoint（.pptx）由统一结构块渲染为 Markdown；对扫描件、图片、旧版二进制 Office、加密或损坏文件、未知格式如实进入“需要处理”。保真边界（PDF 不还原表格结构、Office 复杂表格与图片只保留文字并提示等）以冻结样本的实测记录为准，不在界面伪造成功率或百分比。

## Client 半边

界面通过 Shell 的 `eadp.knowledge.view` 插槽组合，使用官方 slot、service、remote 扩展点；Client 不读取本地文件或调用 Node，文件字节由渲染层读取后以 JSON 传输给 Host，图片资源由 Host 返回字节再在界面转成显示地址。编辑器基于 Lexical 0.49，第三方依赖内联进插件 client 产物。

## 诊断

业务界面不展示技术名词；失败细节只出现在导入记录与“来源与原件”的“处理详情”折叠区。启动核对、后台整理与清单异常写入 Host 诊断日志，不阻断阅读、编辑与保存。

## 未验证与已知限制

- 阶段一的静态构建门禁与真实桌面闭环验证结果以阶段交付记录为准；未经真实桌面验证的项不宣称完成。
- 检索、自动参考、需求依据与固定引用属于阶段二；embedding 与向量混合属于阶段三且当前公开接口不可用。
- 自动转换不承诺任意二进制、加密或损坏文件都能理解；未支持的格式必须走“需要处理”与手工整理路径。
- 用户资料保存在本机应用数据目录，不随工程复制；备份由用户自行管理，删除应用数据会丢失资料。
