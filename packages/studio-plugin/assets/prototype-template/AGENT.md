# 原型工程规则

本文件约束由本模板生成的 `原型代码/` 工程，用于需求验证与合成数据演示。
工程根目录的 `AGENT.md` 是唯一模板规则文件，不创建 `AGENTS.md` 或兼容加载路径。
代码遵循本工程实际配置、当前依赖版本和已确认需求；不升级技术栈、不引入临时兼容层。

## 1. 开工条件与当前状态

- 工作台须通过目标 DSH 发布版已验证的入口加载本文件，并绑定规则版本、需求和官方会话。
- 文件存在不证明加载成功；缺失、未识别、加载失败或版本不符时，阻断普通生成和增量修改。
- 本文是规则契约，不替代文件权限、受控工具、执行前检查和网络限制。
- 当前模板是源码候选，未完成 G0-3；不得把本文新增视为模板已经就绪。
- 当前没有依赖锁文件、精确 Node/pnpm 基线或 `packageManager`，冻结安装尚不成立。
- 当前没有已验证的浏览器静态 Mock 初始化、ready 检查或独立静态预览入口。
- 当前没有独立 `typecheck`、`test` 脚本；lint、构建及浏览器检查均未验证通过。
- 真实服务代理、远程 Mock、生产网关与登录依赖尚未隔离，普通原型任务不能自行修补以开工。
- 维护者补齐并验证工程契约、重新固定模板版本后，工作台才能接入普通原型任务。

## 2. 技术输入与模块边界

- 现有栈为 React 18、TypeScript、Umi 4、Less；使用已有插件和配置，不换框架。
- UI 使用 `@ead/suid`；图标使用 `@ead/suid-icons`，样式沿用 `@ead/antd-style` 与 Less。
- 不从参考工程推断底层 Ant Design 精确版本；声明范围不等于实际安装版本。
- 使用组件前读取当前版本文档、已安装类型或同版本验证样例，记录依据；没有依据不猜 props。
- 扩展组件不能套用原生 Ant Design API；一个现有示例不能证明其它 props 或交互可用。
- 不新增 UI 库、请求库、状态库、包管理器或脚手架；缺项交维护者处理。
- 保留 `config/router.config.ts` 的 Umi 路由结构、hash history 和既有布局边界。
- 保留 locale 插件及 `src/locales/` 的中英文组织方式；新增业务文案按现有键名约定组织。
- 保留既有 `@/*` 别名，不因参考工程目录不同重写 alias 或 tsconfig。
- 当前配置与类型中的别名是否一致，属于工程验收；发现异常报告，不在业务任务中改配置。
- 原型的列表、选项、用户和附件只消费合成数据，平台服务不能成为演示前置依赖。

## 3. 可写区域与维护者保护区

| 区域 | 普通原型任务边界 |
| --- | --- |
| `src/pages/<PageName>/` | 已授权页面的 TSX/TS、局部样式、子组件、页面服务与合成数据 |
| `src/components/` | 已授权的页面间或业务域复用组件；先核对调用方，不扩大成通用框架 |
| 页面局部状态 | 页面内 hooks；确有必要的页面 `model.ts`，不改平台全局 model |
| `src/locales/` | 本次页面文案及对应翻译，不修改国际化插件和加载机制 |
| 已验证的 Mock 数据区 | 合成 fixtures、授权业务场景和 handler 内容，不改初始化与拦截策略 |
| `config/router.config.ts` | 仅在明确授权新增页面时登记该页面路由，保留框架设置与既有路由 |

- 普通任务不得修改本文件、模板来源清单、依赖声明、锁文件、包管理与运行时版本。
- 维护者在明确授权的模板维护任务中可修改保护区并重新验收；该职责与普通页面生成任务区分。
- `package.json`、`.npmrc`、tsconfig、lint/格式化配置、Umi 构建和插件配置由维护者维护。
- 代理、网关、环境配置、Mock 初始化与未知请求策略、共享安全配置属于保护区。
- `src/app.tsx`、认证/登录布局、全局 model、`src/services/api.ts`、全局常量与请求错误插件属于保护区。
- `public/app.config.json` 的名称/base、Docker、发布配置与凭证不由普通页面任务修改。
- 路由授权例外只登记页面路径、组件及必要业务标题；不得改认证布局、生产条件或框架插件。
- 不删除他人改动，不重写无关页面；变更前核对当前任务基础、未提交补丁和授权范围。
- 发现保护区导致阻塞时，保留业务成果并记录具体缺项，不绕过、不加 fallback。

## 4. 页面组织与状态

```text
src/pages/<PageName>/
  index.tsx          # 页面入口、布局与交互编排
  service.ts         # 本页面的数据访问边界
  model.ts           # 仅在共享状态/effects 确有必要时新增
  components/        # 本页面子组件
  mockData.ts        # 可选：本页合成样例，不承担全局 Mock 初始化
```

- 使用 `.tsx`/`.ts`，不照搬参考工程的 `.jsx`/`.js` 页面结构。
- 服务请求集中到页面 `service.ts`；同业务域复用时在域内共享，不建立第二套全局 API 层。
- 页面服务只能调用维护者已验证的本地模拟入口；当前入口缺失时不得改接真实平台 API。
- 纯列表和局部编辑优先使用局部 state/hooks；需要跨组件共享状态或 effects 时才引入 `model.ts`。
- model、service、视图分别承担状态编排、数据边界、呈现职责；避免将整页逻辑堆进全局 model。
- 组件从页面内复用起步，出现实际域内重复再提取；不预防性抽象，不让其它域依赖页面私有实现。
- 类型区分记录、编辑草稿、选项和模拟响应；不滥用 `any`、类型断言掩盖字段不一致。

## 5. SUID 组件选型

先核验当前版本能力，按以下场景选择；不要凭原生组件经验绕过企业组件约定。

| 场景 | 优先组件 | 不默认采用 |
| --- | --- | --- |
| 单/多选下拉，静态或模拟选项 | `ComboList` | `Select` |
| 组织、分类或级联树选择 | `ComboTree` | `TreeSelect` |
| 表单金额输入 | `MoneyInput` | `InputNumber` |
| 列表金额展示 | `Money` | 手写 `toFixed` 或未格式化文本 |
| 数据列表与主表格 | `ExtTable` | `Table` |
| 列表工具栏日期区间筛选 | `FilterDate` | `DatePicker.RangePicker` |
| 工具栏视图/状态快速筛选 | `FilterView` | `Select`、`Tabs`、`Segmented` |
| 页面、表单与表格的滚动区域 | `Scrollbar` | 自行搭建通用滚动容器 |
| 附件选择、预览和管理 | `Attachment` | `Upload` |

- `FilterView` 用于工具栏快速筛选，不替代多条件 Form 搜索区。
- `Table` 仅在极简只读弹窗小表、无分页筛选的纯展示子表，或已证明 `ExtTable` 布局不适用时选用。
- 其它原生组件例外也要说明场景不适用的依据；不做运行时降级或维护两套 UI。
- `ExtModal`、`ActionButton` 等可按实际场景选用，但属性仍须核验当前版本，不能复制未确认接口。
- 有远程 `store` 能力的组件必须接入已验证 Mock；下拉、表格、附件初始化不得隐式请求真实服务。

## 6. Combo、Form 与对象缓存

- Form 内 `Form.Item` 用业务字段 `name` 绑定 `ComboList`；不同时手工传独立 `value`。
- 配置抽成 `{字段语义}Props` 普通对象，以 `<ComboList {...xxxProps} />` 传入。
- 按当前版本接口核验 `reader.extFields` 与顶层 `extFields` 后，采用下表映射语义。

| 位置 | 字段含义 | 示例 |
| --- | --- | --- |
| `reader.extFields` | 模拟 store 响应的原始字段 | `id`、`account` |
| 顶层 `extFields` | Form 或行业务保存字段 | `projectId`、`userId` |

- 两层字段按顺序一一对应；`onChange` 的扩展值使用顶层业务 key。
- 不把 store 的 `id` 直接映射到顶层单据主键 `id`；子表 Combo 同样使用行业务字段名。
- 选择、回填、联动、清空和编辑回显全部验证；清空不能残留上次的关联字段。
- Combo 系的 props、store、reader、onChange 不用 `useMemo`/`useCallback` 包裹。
- store/reader 无渲染依赖时优先模块级常量；有依赖时使用普通 const 或字面量，不冻结旧选择条件。
- `ExtTable` 的整个 store 对象不用 `useMemo` 包裹，按当前模拟条件传普通对象。
- columns、rowSelection、工具栏及非 Combo 回调可按实际需要缓存，不把该限制扩大到所有 React 对象。
- 缓存规则来源于企业使用约定；若当前版本类型或行为冲突，报告并由维护者验证，禁止猜测补丁。

## 7. 根上下文与附件只读

- 保留现有 `src/app.tsx` 的 `ConfigProvider > App > 页面` 包裹顺序。
- 主题、locale 与反馈上下文由该入口提供；页面不重建全局 Provider，不使用脱离上下文的反馈调用。
- 附件仅使用合成名称和本地样例、浏览器内存文件；不得上传生产服务或携带真实需求附件。
- 只读意味着保留查看能力：禁止上传、删除，仍允许已授权的本地预览和下载。
- 参考接口约定为 `allowUpload=false`、`allowDelete=false`，保留 `allowPreview`/`allowDownload`。
- 使用这些属性前必须核验当前安装版 `Attachment` 的类型与行为；不支持时报告缺项，不发明 props。
- 不用 `disabled={readOnly}` 实现只读；完全锁定或 loading 才使用经核验的 disabled 行为。
- 不在整体 disabled 的 Form 内靠猜测恢复附件交互；附件查看区域与编辑禁用区域分开组织。
- 不引用参考工程专有的 `AttachmentInteractionScope`；本模板没有该 helper，不能虚构实现或导入。
- 验证详情只读、编辑可变更、loading 完全锁定；本地预览/下载不能偷偷触发真实网络调用。

## 8. 金额、日期与交互标准

- 金额输入与展示分别使用经核验的 `MoneyInput`、`Money`，列表金额列右对齐。
- 精度、币种、零值、负数、空值与舍入按已确认需求表达，不用随意 `toFixed` 代替规则。
- 日期区分日期与时间，统一页面格式；空值明确展示，不能伪造当前时间。
- 时间范围筛选检查边界、跨日、开始晚于结束及清空；时区语义不明时保留待确认项。
- 操作名称用业务动词；按钮可用、禁用、执行中和失败状态与模拟业务条件一致。
- 提交先校验必填与格式，执行中防重复点击；错误保留可修正输入，不显示虚假的成功反馈。
- 详情只读与编辑草稿分离；取消/撤销编辑恢复原记录，不把草稿提前保存到列表。
- 删除、作废等模拟破坏性操作明确确认对象；反馈与实际内存状态一致。
- 验证键盘操作、合理焦点、错误定位、长文本、窄窗口、滚动与分页，不只检查首屏截图。

## 9. 合成 Mock 与必需场景

- 只生成合成业务数据；不复制真实账号、个人信息、内部附件、令牌或生产数据库样例。
- 推荐固定 seed、浏览器会话内存 CRUD；刷新重置，提供明确的“重置演示”操作。
- 各浏览器会话独立，不把模拟保存描述为后端持久化或跨用户共享。
- 合成页面必须覆盖：正常列表、空数据、加载、请求错误、详情、编辑、取消/撤销和保存失败。
- 选项、联动、日期/金额校验、分页筛选、删除确认与重置按需求补齐，不能只做成功路径。
- Mock 初始化完成前阻断相关交互并显示诊断；未知请求必须拒绝，不向真实服务透传。
- 不绕过页面服务直接使用 fetch、XHR、WebSocket、表单提交或第三方 store 访问真实业务目标。
- 静态资源与模拟 API 分开；字体、脚本、图片和附件仅用获准本地/同站点资源。
- 开发服务可演示不代表静态产物可演示；远程 Mock 服务不能成为本地或分享站点的运行依赖。
- 当前 `start:mock` 只切换开发环境变量，不能证明静态 Mock、未知请求拒绝或网络隔离。
- 当前 production 仍使用真实网关，认证布局仍检查用户；现有代理也指向真实服务和远程 Mock。
- 这些问题需维护者修复并做负向验证；本文禁止条款本身不能拦截网络，未通过前阻断使用和发布。
- 不预设 MSW 已存在；若维护者采用 Service Worker，再验证其初始化、scope、安全上下文和更新。

## 10. 命令、预览与工程门禁

以下为现有 package scripts，统一从原型工程根执行；使用 `pnpm run`，不混用 yarn。

| 命令 | 当前含义与限制 |
| --- | --- |
| `pnpm run lint` | 串行脚本/样式检查；存在命令不代表已通过 |
| `pnpm run lint:script` / `pnpm run lint:style` | 分别检查脚本、Less；不能代替类型检查或行为验收 |
| `pnpm run build` | Umi 构建且 `ESLINT=none`；生产关闭类型检查，不能替代 lint/typecheck |
| `pnpm run start:mock` | 候选 Mock 开发命令，尚未验证纯静态演示，不作为已就绪预览入口 |
| `pnpm run start` | `MOCK=none` 的真实后台开发路径，禁止作为普通原型默认启动命令 |

- `npmClient=pnpm` 只确定工具方向，精确 pnpm/Node 与依赖组合仍须维护者冻结；不臆造安装版本。
- 当前未定义独立 typecheck/test、ready 判定或静态 preview 命令；缺项阻断，不发明可通过的命令。
- Docker 引用 `dist` 仅是候选产物线索；实际输出目录、base path、hash 路由刷新和资源路径须实测。
- 检查记录绑定实际模板版本、代码提交、环境、命令和结果；失败或未运行不得写成通过。
- 工程验收必须包含冻结安装、规则加载/执行保护、lint、独立类型检查、构建与静态行为走查。
- 必须验证 Mock 未 ready、未知请求、组件副作用及绕过服务边界时拒绝真实网络访问。
- 页面按变更风险做必要验证，不机械增加镜像实现的测试；工程门禁及网络边界负向验证不能豁免。
- 预览只在工作台提供的受控入口启动并按 ready 契约确认；普通页面任务不操作发布凭证或服务器。
- 普通生成任务不修改工程配置以绕过失败；保留具体错误和未完成项，交维护者修复后重验。
