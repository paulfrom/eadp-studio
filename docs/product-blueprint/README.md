# 产品构想图

`eadp-studio-product-blueprint.drawio` 是面向业务与管理层的产品构想图，单文件三页，用 draw.io / diagrams.net 直接打开编辑。

与 [`docs/architecture/`](../architecture/README.md) 的技术架构图分工：产品图回答"为什么做、做什么、谁来做"（业务语言）；技术图回答"由哪些部件组成、怎么连、怎么造出来"（实现语言）。两图不重复论证，也不互相矛盾。

## 三页各回答什么

| 页 | 内容 | 读法 |
| --- | --- | --- |
| 1 为什么 | 现状痛点 → 工作台 → 三条价值 | 三条横轨，一一对应业务推进、知识沉淀、资产复用 |
| 2 做什么 | 五段主线、沉淀物、复用支线、价值落点 | 主线自上而下，复用支线在下方 |
| 3 谁来做 | 十个动作 × 四类角色的权责矩阵 | 同一动作只出现一次，单元格写该角色在此动作中的能力 |

## 读法

- **卡片**：上方是大写类型（现状 / 产品 / 价值 / 阶段 / 沉淀资产 / 复用步骤 / 价值落点），中间是名称与职责，右下角是脚注（来源、技术或落点）。
- **关系徽标**：两行，第一行是动作，第二行是括号里的要点。颜色区分关系性质：主流程、状态变更、数据读取、异步。
- **虚线分组框**：把同类的卡片圈在一起（今天的做法、工作台带来的改变、复用支线）。
- **印章**：右上角标注本页视角与评审状态（草案）。

## 角色能力图例（第 3 页）

| 类别 | 含义 |
| --- | --- |
| AI 自主 | AI 可独立完成，不改变成果状态 |
| AI 协同 | AI 出料，必须有人点头才生效 |
| 用户必须动作 | 用户的显式操作才生效 |
| 平台落库与判定 | 留痕、版本与"被项目接受"的判定 |
| 研发动作 | 研发侧的动作 |
| 不参与 | 该角色在此动作中不出手 |

**铁律**：AI 只提议、不落笔。任何「生效」都必须由用户显式动作或平台判定产生。

## 约定

- 图上不标"代码就绪 / 未发行验收"一类状态。
- 术语以仓库根目录 `CONTEXT.md` 为准；材料名（场景确认版、需求确认版、原型基线、开发指导 PRD）与产品界面的叫法一致。
- 徽标是独立单元格，不随连线自动移动；移动连线后需要手工把徽标移回空白处。
