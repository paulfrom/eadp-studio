# 一致性对比与场景、需求文件及业务流程分离

场景和需求表达不同粒度的业务内容，需求细化也可能发现需要反向修订场景的事实。用户明确要求项目提供独立的一致性对比能力：AI 查找关联文件并比较场景与需求的业务一致性，发现差异后由用户决定忽略、处理或提醒，以及采用哪一侧的内容修订另一侧。

每个场景或需求维护同一个文件，历史由 Git 保存，不为各历史版本建立平行的业务文件。一致性差异列表和处理结果存协同后台，与文件本身及材料、任务的业务状态分开；差异状态不写回材料文件，也不作为材料确认或其他流程的门禁。对比失败应如实表达，不能伪装成没有差异，也不能阻止流程继续。

一致性对比只读取本地实际文件，不执行 Git 命令，不读取 Git 历史作为对比输入，也不自动拉取、切换或提交材料。手动入口与场景／需求确认后自动发起的非阻断对比都遵守该边界；输入用本次实际读取的项目相对路径和内容 hash 标明，不上传本机绝对路径。存在尚未确认的编辑时按已有本地任务状态标为草稿，不调用 Git 判断内容状态，也不把本地内容描述成已确认 Git 内容。本地关联文件缺失时记录未覆盖范围，不用 Git 补齐。材料原有确认流程及其 Git 历史管理保持独立职责。

工程方案中，交给模型的内容与计算 hash 的字节来自同一次本地读取；不生成持久文件副本。关系查询仅使用后台已有协同控制字段，不调用会触发 Git 读取或后台同步的固定版本加载路径。确认回执不等待自动对比完成，缺失输入也不得排队补取。结果过期只描述其与本机可见内容的关系，后台不能据此判断其他成员私有草稿。新比较保留独立记录，不覆盖旧结果或继承其处理结论。

对比任务只开放受控本地读取和关系目录能力，不开放终端、Git、文件写入、同步或材料确认工具，不能只依赖提示词限制行为。路径须校验实际解析位置仍在当前项目允许的业务材料范围内，拒绝目录穿越或符号链接越界；越界、缺失或不可读均如实记录范围不足，不扩大读取范围补齐输入。

查找从已有场景／需求关系出发，再在当前项目本地业务材料中发现潜在关联，展示依据，不自动改变正式关系。差异的“登记处理结果”只更新后台记录；“修改相关材料”另行进入建议、采纳及修订流程。忽略与提醒只操作后台记录，不要求再次对比或材料确认后才能登记处理结果。

取消整体关联冻结和强制同批确认，各材料独立占用、修订及确认。选择修改方向后，先生成拟修改文件清单和建议，用户采纳后才写入对应草稿，修改后的材料仍须独立确认。差异处理结果、修改方向选择都不等于另一材料已经修改或确认；原有材料业务质量、权限和 Git 接受等检查保持各自职责。

该边界允许用户在差异未处理、被忽略或检查失败时继续业务工作，同时通过后端独立记录追踪对比与处理结果。以一致性检查阻断确认、要求先裁决差异才能确认，或将差异处理与材料确认捆绑为一个事务，均不符合本决议；旧批次和自动关联来源升版实现也须按新设计删除或改写，不保留兼容层。本轮仅更新设计，未修改实现。工程方案沿用项目读写权限、带修订号的并发更新，以及后台标记配合项目内界面提醒；不新增外发消息或定时通知通道。具体契约见[需求协同设计](../design/02-requirements.md)，工程细化待整体确认。

差异更新使用差异记录自身的修订号，与材料占用、材料修订及项目认可头分开。后台采用专用结构化契约和长度限制，只接收必要差异摘要、输入定位及用户处理事实，不接收完整材料、完整 diff、原始模型响应或会话；不能以既有按字段名删减的通用清洗代替输入约束。登记为已处理或忽略仍不代表材料内容已经一致。
