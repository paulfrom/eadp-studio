# 协同后端临时读取 Git 固定正文校验，不保存正文

2026-10-14 已确认（正文与校验边界沿用）：业务确认 API 只接收固定 Git 引用、内容哈希与控制元数据，不接受客户端上传正文；协同后端可以按当前操作者既有 Git 读取授权，临时读取该引用的 MD，在内存中核验实际字节哈希及实体、分类、来源、场景和前置关系与上报元数据一致，校验后丢弃正文。Git 仍是正文的持久保存方，后端不将正文写入数据库、日志、文件缓存或错误响应。

仅比较客户端提交的两个哈希，不能发现“MD 写依赖 A，客户端却上报无依赖”；只信任客户端签名或检查 ID 也不能独立证明内容一致。采用后端读取固定 Git 内容的常规验证方式，不建立独立证明平台；读取失败、权限不足、哈希不符、字段不一致或结果未知均阻断受理，不能回退为信任客户端声明。

读取对象限定为项目已登记仓库、不可变提交 SHA 和经校验的仓库相对路径，不接受任意 URL，也不得由通用服务凭证扩大真实操作者的读取范围。Git 读取与解析在数据库事务外完成，事务内重新核验占用、revision 和业务条件。结构化校验不能替代作者对业务依据及验收条件的确认，也不能单独证明真实用户确认动作。

2026-10-15 身份与取用方式修订：工作台只登录协同后端，由独立协同会话确定操作者；后端将该协同用户绑定到已存在的 GitLab 数字用户 ID，不再要求客户端提交 GitLab OAuth token。后端通过受控管理端配置的 `SEI_GITLAB_TOKEN` 读取固定字节前，必须实时核验绑定 GitLab 用户对该仓库的有效成员权限（含继承、状态和到期），不得采用管理 token 本身可见范围代替成员权限；无权限、绑定未解析、成员状态未知或权限变化均阻断。读取正文后的业务事务仍复核身份、当前占用、revision 及其他门禁，必要时重新核对权限，避免借管理身份扩大授权。

管理 token 只留在后端运行配置，不发送桌面、client、Agent 或业务 API 调用方；桌面本机 Git 凭据与协同会话独立。上述改变只修订可信身份和读取授权的实现边界，正文在内存校验、事务外读取/解析、事务内条件复核及不持久保存正文的规则不变。完整身份和建仓决策见 [协同登录与后端建仓](0003-studio-auth-and-project-provisioning.md)。

该决策确定数据和校验边界；真实 Git 授权读取、字段解析契约、超时及大小限制、正文不落盘/不进日志、伪造及重放拒绝仍须 G0 实测。
