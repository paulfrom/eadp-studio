# 协同后端临时读取 Git 固定正文校验，不保存正文

2026-10-14 已确认：业务确认 API 只接收固定 Git 引用、内容哈希与控制元数据，不接受客户端上传正文；协同后端可以按当前操作者既有 Git 读取授权，临时读取该引用的 MD，在内存中核验实际字节哈希及实体、分类、来源、场景和前置关系与上报元数据一致，校验后丢弃正文。Git 仍是正文的持久保存方，后端不将正文写入数据库、日志、文件缓存或错误响应。

仅比较客户端提交的两个哈希，不能发现“MD 写依赖 A，客户端却上报无依赖”；只信任客户端签名或检查 ID 也不能独立证明内容一致。采用后端读取固定 Git 内容的常规验证方式，不建立独立证明平台；读取失败、权限不足、哈希不符、字段不一致或结果未知均阻断受理，不能回退为信任客户端声明。

读取对象限定为项目已登记仓库、不可变提交 SHA 和经校验的仓库相对路径，使用操作者的有效来源读取授权，不接受任意 URL 或由通用服务凭证扩大读取范围。Git 读取与解析在数据库事务外完成，事务内重新核验占用、revision 和业务条件。结构化校验不能替代作者对业务依据及验收条件的确认，也不能单独证明真实用户确认动作。

该决策确定数据和校验边界；真实 Git 授权读取、字段解析契约、超时及大小限制、正文不落盘/不进日志、伪造及重放拒绝仍须 G0 实测。
