## 术语（同时写入 `CONTEXT.md`）

- **讨论结论**：本轮对话中被用户确认的明确业务结论，尚未落盘。
- **写入提议**：Host 记录的待执行写入，包含提议 ID、目标文件、正文 baseHash、模板固定引用、项目上下文 hash、依据 ID 集合；仅由用户明确动作消费。_Avoid_: 采纳、建议批次、AI 建议。
- **整篇写入**：一次把完整正文写入目标文件的受控动作，无条目、无分段、无部分写入。
- **附件入口**：会话输入区的资料入口，承载导入、读取状态、读取范围、失败重试与正式依据勾选。
- **任务**：一个 worktree 归属单元；同一场景的多个会话共用同一任务，会话是任务下的会话记录行。
- **本机收整**：后台已接受之后，把主目录同步、释放运行资源并清理本次 worktree 与执行登记的过程。

## 保存与写入契约

用户明确要求生成或更新时，AI 才根据当前材料正文、`CONTEXT.md`、固定模板和已读资料组织**整篇正文**。
讨论阶段 AI 只归纳结论并主动提问「是否写入《目标文件》」，可一次提出两类目标：项目 `CONTEXT.md` 与当前材料正文。
Host 把每次提问记录成一条写入提议，提问本身不构成授权：
- 提议内容：提议 ID、目标、baseHash、模板固定引用、`CONTEXT.md` hash、依据 ID 集合、创建时间。
- 触发条件（可判定）：本轮出现新的明确结论；或阻断性待澄清项已清空且核心规则与验收条件已声明。无新结论不重复提问。
- 消费：用户明确动作（按钮或「是」）才消费；回答否或未回答不写文件，继续对话；同一批结论被拒后不再询问，直到出现新结论。
- AI 不能自行判断已获授权，也不能自行写文件；Host 不解析自由文本推断同意，否定与歧义一律按未授权处理。

写入沿用现有受控能力：Host 校验 `expectedHash`、模板绑定与依据后一次整篇写入（无批次、无条目、无分段），失败不丢用户内容。
写入后返回变更摘要（改动的章节与原因、用到哪些已读资料、仍缺哪些业务答案），并提供基于本地差异的撤销；撤销是一次新的受 hash 检查的写入。
正文 hash、模板固定引用、`CONTEXT.md` hash 或所选依据集合任一变化，提议即作废，须重新提问；不得按旧提议覆盖。
同一提议重复消费只生效一次；流式未完成、取消或写入失败不产生半篇正文。

生成保存与正式确认分离；已有 AI 修复继续遵循独立授权边界（ADR-0001），普通对话不能继承其自动确认权，写入提议也不构成确认授权。

`CONTEXT.md` 的归属与接受：本计划采用**项目级受控配置变更**，复用模板发布链路（独立候选、独立 worktree、独立接受），不进入场景确认批次，避免让一个任务的材料候选依赖另一个任务的接受状态。
（2026-10-22 修订：按交接文档与已落地后端，`CONTEXT.md` 允许随场景候选同批冻结与接受；仅更新项目上下文时仍走上述项目级链路。此段旧表述待清理。）
本地保存落在任务 worktree 派生出的 `CONTEXT.md`，不自动 commit；接受后主目录只读同步到认可头。
共享 `CONTEXT.md` 须比较任务基线、本次修改与最新接受版，不能用旧整份文件覆盖新内容；文本或语义冲突回到对话解决。
不得借此开放任意根目录文件：白名单只有项目根的 `CONTEXT.md` 一个路径。

## 两个独立完成判据

### A. 场景已被项目接受

- 用户以显式动作确认其阅读过的精确文件快照；AI 不承担审批。
- 四项门禁全部通过：业务内容、资料与引用、版本与占用、模板结构（本机偏好关闭时不检查该项）。
- 占用令牌有效且与用户、设备、材料版本一致；本产品阶段一没有独立权限模型，权限即占用身份，不新增权限系统。
- 候选提交父为认可头，变更路径仅限本次材料、`CONTEXT.md`、所选依据与关联文件，逐文件 hash 匹配。
- `complete` 返回接受，且后端事务保存确认版本与固定引用，`integration.status=accepted`。
- 之后可能出现后继接受提交；本机同步可使用包含该候选的最新后台认可头。
- 结果未知时查询原操作，不创建重复确认；单独 commit 或 push 成功均不等于接受。

### B. 本机收整完成

- 已满足 A；主 checkout 已包含本次接受提交（或其后继认可头），不为本次收整而回退。
- 本任务范围内无未推送成果：本次 worktree 无未提交变更、无待清理的已跟踪文件。
- 无未消费的旧写入提议、无生成中的会话、无仍在观察的引用；本任务会话、观察、预览已释放。
- 本次 worktree、临时分支与执行登记已清理，`git worktree list` 与登记一致，收尾步骤逐项持久化并幂等。
- 历史会话、附件与稍后需求拆分可从不依赖待删目录的存储读取；有价值 ignored/untracked 材料已归档并记录 SHA-256，保留旧 HEAD 引用。
- 主目录中用户的其他改动与未跟踪文件**不**自动 stash、reset、clean 或覆盖；这类内容只记录为「待同步」，不阻塞本任务收整。
- 后台已接受但本机同步或清理失败时，状态为「已确认待同步」或「已确认待清理」，各自有明确重试动作；本机失败不回滚业务接受状态，也不重复确认。
