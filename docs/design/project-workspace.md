# 项目文件夹与程序数据分离

2026-10-30 用户已确定：提供可更改的默认项目位置，创建或首次打开项目时可单独选择项目文件夹。已有本机项目不做迁移；用户明确授权清除当前用户的本地项目现场，按目录误删后重新拉取处理。该授权不涉及协同后端或 Git 远端数据。

## 目录归属

| 内容 | 所在位置 | 生命周期 |
| --- | --- | --- |
| 随包 Host、模板、Node、pnpm、Git、浏览器 | 程序发行目录 | 由安装与更新管理，不写入用户项目 |
| 账号凭据、默认位置、设备身份、项目位置索引、跨项目队列顺序 | 系统凭据存储与应用数据目录 | 属于本机程序设置，不随项目提交 |
| 主仓库 | `<项目文件夹>/repo` | 存放场景、需求、交接、原型代码及 Git 历史 |
| 项目过程记录、材料保存回执与可恢复字节、导入资料、待发送指令与编辑缓冲、任务工作树、检查报告、浏览器证据、候选、发布与归档现场 | `<项目文件夹>/.eadp/users/<账号>` | 归属于项目，不能当作可重建缓存；不提交主仓库 |
| 项目归属标记 | `<项目文件夹>/.eadp/owner.json` | 绑定项目与本机账号，拒绝覆盖其他项目或账号的现场 |
| 依赖安装、Umi 构建、预览执行快照 | 系统临时目录中的受管短路径 | 可重建，受任务校验与释放控制；不占用源工程目录 |
| 固定版本只读镜像缓存 | 应用数据目录中的受管缓存 | 可从远端重建，随 Host 释放 |
| 原生会话日志与宿主会话索引 | 官方宿主统一会话目录 | 当前上游限制，见下文 |

默认位置为 `~/EADP`，与程序目录分离。每个自动生成的项目文件夹使用截短的仓库名称与八位标识，不再叠加 `users/<账号>/project-<完整 UUID>`。用户选择的文件夹是项目根，程序在其中创建 `repo` 与 `.eadp`；不会自动在用户已选目录之外再放一份编辑现场。

## 用户操作与可信边界

- 设置中的“项目位置”更改默认位置；创建或打开项目对话框显示默认位置并提供官方原生目录选择器，取消不会提交或改动设置。
- 用户首次获取项目可选择空或非空文件夹，均从 Git 远端克隆仓库；空远端克隆后再写入初始化文件和推送首次提交。根目录已有文件保留原位，未经归属登记的 `repo` 若有内容（包括已有 Git 仓库），先整体改名为相邻的 `repo.backup-<时间戳>-<唯一标识>`，再克隆；此保留仅用于恢复唯一原文件，由用户核对、取回所需内容后自行清理。不属于本项目和账号的标记、程序目录及其别名仍拒绝写入。已归属本项目的仓库按正常打开或重试恢复，不重复克隆覆盖活动现场。
- 目录在后台初始化开始前随本地操作固定。默认位置后续变化、重试或重启不改变同一初始化的目标。
- 已登记项目沿用原位置，重新打开不提供隐式移动。Git 与业务模型不接收任意磁盘路径，只有可信 UI 的项目命令接收目录，Host 负责校验和登记。
- Client 复用官方 `ctx.uiWorkspace.pickDirectory()`，不读取本机文件系统，不新增 Electron 通道。

## 保存与恢复

程序索引保留设备身份及项目位置。项目过程记录按项目独立持久化；跨项目串行调度保持原有行为，程序侧队列只保留顺序、选择和幂等指纹，指令正文和编辑缓冲保存在对应项目。

整个项目文件夹被外部删除时，索引仍能读取，其他项目继续可用；读取状态及保存另一个项目不会重建被删目录。用户显式打开后从远端重新获取，已丢失的未提交内容不会被声称恢复。若仅删除仓库或留有文件，则沿用现有归属核对及现场保护；损坏的私有记录拒绝覆盖。程序索引丢失而项目私有记录仍完整时，重新登记须先验证并恢复私有记录，再保存索引，避免空集合覆盖草稿。

状态格式使用当前格式 3，不引入旧路径回退或数据迁移。用户已授权本次清理，执行范围须据当前账号和已登记归属核实；保留登录凭据与设备身份以供重新拉取和核对原占用，不删除远端项目、版本或占用事实。

## Windows 执行与原生会话限制

选择干净且较短的项目目录能减少路径累积，但不能保证所有子工具支持长路径，也不能消除文件占用导致的原子替换失败。保留受管短路径构建快照及同一次原子替换的有界重试。源文件、任务授权和构建输入指纹仍按原规则核对。

官方 `SessionCommandController.create` 的 `cwd` 只决定工作目录，没有逐会话存储根参数；`JsonlSessionPersistence` 使用全局 `Config.root`，官方持久化接口没有迁移、导入或重定位能力。因此原生日志仍由宿主管理，不能宣称复制项目文件夹即可携带全部原生对话历史。不手工移动压缩日志，不新增绕过；缺口登记在 `docs/blocked-upstream.md`。

参考已验证模式：[JetBrains 项目容器](https://www.jetbrains.com/help/idea/creating-and-managing-projects.html)、[Electron 应用数据与会话数据目录](https://www.electronjs.org/docs/latest/api/app)、[Windows 路径限制](https://learn.microsoft.com/en-us/windows/win32/fileio/maximum-file-path-limitation)。项目文件归项目、设置和缓存归程序；路径执行能力仍由实际工具链决定。
