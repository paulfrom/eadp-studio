# 桌面开发队列、开发占用与 Git 同步协议

状态：2026-10-31 用户确认原生会话持续交互、开发段进入时核对占用及 commit，Git 不一致由桌面同步并更新协同记录；首次完成释放与后续纠偏领取规则保持。主要流程已落入契约、SQL、协同后台、Host 和桌面 UI。本轮仅做静态验证，最终桌面验证由用户执行。远端引用变化与占用释放之间的跨系统竞态仍未解决，真实桌面完整闭环尚未验收。入口见[需求确认](../02-requirements.md)、[原型工作台](../03-prototypes.md)及[协同契约](collaboration-contract.md)。

## 1. 已确定的职责

- 需求确认成功后自动进入本地开发队列，桌面串行执行，一项结束后自动推进下一项；需求确认结果不依赖后续入队或开发成功。
- 本地持久保存顺序、进度、会话、工作现场、成果核对、纠偏输入和待恢复操作。协同后端不调度本地队列，不保存模型会话或逐项核对过程。
- 后端权威控制同项目同需求的开发占用，并保存该占用操作所绑定的 commitId、受管远端引用及必要身份、代次和幂等记录；本地同步缓存不能授予开发权。
- 是否允许新开发以当前占用标识为准：未占用时不要求 commitId 与远端一致，原子领取即可；已占用时返回正在开发中，不能以 commit 相等绕过。管理员可以主动修改标识，不以 Git 同步成功作为管理操作的前置。
- 首次开发、后续纠偏及中断恢复进入开发段时，由 Host 取得或重新核实占用及 commit。同一有效开发段的原生消息与工具执行沿用该授权，本地持久保存逐轮操作，不为每条消息或每次工具调用重新请求远端许可。断网或结果未知时保留现场，不能凭旧缓存进入新的开发段。
- 首次 AI 开发完成：可信 Host 完成 hook 自动固定代码、提交并推送远端，后端核验 commit 后解除占用，本地成果进入待核对并继续下一项。
- 纠偏：重新原子领取，AI 改完可自动提交、推送并同步 commit，但保留开发占用。用户最后确认完成时，再固定当前成果、推送并请求后端核验及解除占用。这一释放时点已由用户单独确认。
- 逐需求核对与项目整体原型接受分别表达。自动上传成果不自动改项目认可头、不自动生成原型基线；整体接受仍沿用项目受控集成。

## 连续原生对话与内部执行事项

用户在原生会话中直接提出后续修改、跨需求调整及运行要求，不先创建“补充事项”、命名事项或选择任务类型。Host 负责识别指令实际涉及的需求、复用当前会话及管理执行记录；内部事项、分支和占用继续保留其隔离及追踪职责。新需求范围须按实际权限与原子占用规则取得授权，不能把跨需求自然语言等同于绕过协同互斥。

同设备原事项优先恢复。其他账号／设备占用时保留原输入，反馈占用归属与实际可执行的处理路径，不只返回“正在开发”；撤销其他设备许可须有明确授权。持久化、网络与模型执行失败独立反馈真实原因。删除公开新建入口不删除已有草稿、未确认发送请求、活动任务、会话或工作树；尚未投递的唯一输入保留在诊断及原操作恢复入口，不冒充已发送。

## 2. 原子领取及 commit 核验

所有占用状态变化携带真实需求身份、operationId、commitId 和由后端登记规则确定的 repository／remoteRef；更新已有占用还须带当前 claim 身份及 generation。commitId 是完整 Git 提交 ID，不是文件 hash、需求版本或任意客户端摘要。

占用标识为未占用时，后端不读取远端来校验领取请求的 commitId 是否一致；携带的 commitId 用于记录本次开发起点，远端提交不一致或暂时无法读取均不能成为空闲领取的阻断条件。占用标识为已占用时返回正在开发中，而不是通过 commit 比较推翻标识。

已有占用的成果同步与正常完成释放仍从真实远端核对指定成果 ref 与 commitId 是否相等；只证明提交对象存在、可达，或比较本机 HEAD，均不构成远端一致。引用必须归属该项目和事项，不能用无关分支证明一致；成果未推送、不一致或无法核验时保留占用，另走同步恢复。管理员主动修改标识不受此成果同步校验限制。

领取使用现有数据库事务与同需求 active 唯一约束，不能拆成“查询空闲”和“设置占用”两个调用：

1. 验证账号、项目、需求和请求字段；commitId 须携带，但不预先查询 Git 或检查一致性。
2. 短事务内检查原 operationId；相同请求重试返回原结果，不重复领取，相同键不同输入拒绝。
3. 以同需求当前标识判断：已占用则返回“已在开发中”，不覆盖占用者；未占用则在同一事务内置为占用并登记 commit 与代次，不附加远端 commit 一致性条件。
4. Host 获得确定成功结果并持久保存后才进入开发。响应丢失查询原操作，不能换键重领或按缓存推断成功。

重启恢复已有占用使用原 claim／代次核实身份，不把“本次同一占用仍有效”当作他人冲突，也不能依据历史成功回执复活已经解除的占用。新一次纠偏则必须重新领取；即便原占用者仍是本人，也不能直接复用已失效代次。

### 2.1 桌面进入核对与 Git 同步

开发段是进入／恢复时持有一次有效许可的连续开发过程，不等同于原生会话或模型的一条消息。Host 进入时核对需求占用、事项身份、当前本地提交及受管成果引用；commit 匹配即进入，不额外发起 Git 拉取或协同记录更新。不匹配时，桌面按已有受管分支同步能力获取远端提交、核对归属并同步本地现场，成功后才更新协同服务占用记录中的 commitId。远端更新指协同记录更新，不是向 Git 远端推送代码。

同步前持久保存原操作、旧／目标提交及步骤；未提交代码、未保存缓冲、分叉或冲突须保留，不能 reset、覆盖或通过临时备份掩盖现场。拉取失败不更新 commitId；协同更新回执未知时查询原操作，不重复拉取或改用新键。此同步规则在桌面执行，不改变后端原子领取的唯一性，也不要求后端运行 Git 合并。

首次成果完成释放后，原会话保留；继续修改重新进入开发段并领取。纠偏段持有的有效占用沿用到最终确认，不按每条原生消息反复领取。暂停、退出、账号变化、已知撤销及崩溃后不沿用进程内许可；恢复重新核对，旧代次不复活。

首次开发尚未产出时，原生 queue／steer 补充和澄清答复仍属于该首次开发段，不因多了一条用户消息就改成成果纠偏。完成 hook 必须等工具与原生 nextTurn／nextStep 队列全部收敛后固定首次成果；首次成果完成并释放后开始的新修改才进入纠偏领取流程。

管理员主动修改标识时，在权限检查后的同一事务中更新标识与代次，并记录操作人、时间、原因及携带的 commitId，不要求先完成 Git 一致性核验。置为未占用后，后续请求按空闲领取规则处理；旧客户端和晚到 hook 不得使用旧代次解除新占用或继续取得写入许可。本地接收到标识／代次变化后刷新缓存；未提交成果保留，不因管理操作删除代码或会话。

远端 Git 读写与数据库事务不构成一个跨系统原子事务。沿用受控成果引用、条件推送及原操作恢复，数据库短事务内重验占用和代次；远端读取不持有长数据库事务。核验后远端再次变化、旧客户端晚到推送等竞态必须在实现与验收中覆盖，不能仅靠 commitId 声称已解决。

当前缺口：后台读取任务分支后才进入数据库事务释放占用，Git 服务若在读取后更新该引用，数据库仍可能按旧读取结果释放。条件推送只约束单次引用更新的预期值，不能使 Git 更新和数据库释放原子化，也不能阻止已发出或绕过 Host 的晚到推送。需要 Git 服务端可验证且不可绕过的引用写入约束，与占用代次及释放共同协调；在该机制实施并验证前，本协议的该竞态不能视为已解决。

## 3. 状态转换

| 触发 | 远端占用动作及 commit | 本地结果 |
| --- | --- | --- |
| 确认需求 | 仅持久入队；到实际开发前检查标识，未占用则原子领取并记录起点 commit，不校验其远端一致性。 | 待开发；领取成功才开始写入。 |
| 首次开发完成 | 自动 commit／push；远端确认成果 ref 等于 commitId 后，用原 claim／代次解除占用。 | 待用户核对；自动推进下一项。 |
| 用户发起纠偏 | 重新原子检查标识并领取，带 commitId；未占用不要求远端一致，已占用则拒绝起写。 | 保存纠偏输入，领取成功后执行。 |
| 纠偏 AI 开发完成 | 自动 commit／push 并同步新的 commitId；标记仍为开发中。 | 等待用户核对，仍可继续反馈纠偏。 |
| 用户最后确认完成 | 校验当前所阅成果；提交并推送，再携带最新 commitId 请求后端核验与解除占用。 | 核验、解除均确定成功后显示确认完成。 |
| 进程中断或退出 | 不因中断自动解除占用，不发送开发完成事件。 | 保留现场与操作阶段，重开后恢复。 |

没有代码变化时复用现有提交，不制造空提交；按当前阶段区分仅记录 commit 与成果核验。需求完成后运行或检查原型时，若 Host 为本次运行重新领取占用而 AI 未修改代码，完成轮次须核验当前提交与受管远端一致、释放本次占用并恢复运行前的需求核对状态；运行失败同样不能把纯运行变成未释放的纠偏。AI 实际修改代码后仍按纠偏处理，保留占用至用户最终确认。普通客户端取消按其授权和同步协议处理；管理员主动修改标识走专属权限及审计，不要求远端一致或可达，不能把普通客户端同步失败冒充管理员操作。

首次成果未经纠偏、占用已经解除时，用户认可仍须核对实际所阅 commit 和远端状态；不为完成一次只读核对伪造新的开发占用，也不使用已失效 claim 再执行解除。若用户确认前还有代码修改，则先进入纠偏领取流程。

释放开发占用不删除未接受代码、会话和纠偏输入。释放后原 token 不再允许写入；后续整体项目接受须核对当前成果及并行改动，不能用其他需求的剩余占用夹带已释放需求的过期改动。

## 4. 完成 hook 与耐久恢复

复用 DSH 官方 `session/event` 的 `turn/end` 与现有适配器，不新增从聊天正文猜测完成的入口。`packages/studio-plugin/src/host/adapters/dsh/sessions.ts` 已传递 `turn-ended` 及原因；普通 assistant 消息、blocked、max-tokens、interrupted、取消或错误均不能作为开发成功完成。

正常 completed 也只表明一轮结束。Host 须核对该轮属于已授权开发操作、开发成果条件满足、工具写入已收敛以及适用工程检查结果，再执行完成 hook。纯问答或澄清轮次不提交或释放；未达到条件时保留实际进度。检查不代替用户业务核对。

hook 在副作用前持久保存需求、原操作／run 标识、claim 代次及阶段，按“成果固定 → commit 已知 → push 核验 → 后端状态同步 → 本地待核对／队列推进”记录进度。重复事件只补未完成步骤，不重复提交、不重复释放、不多推进一次队列。纠偏 hook 的后端步骤只同步 commit 并保留占用，最后释放由用户确认操作执行。

提交成功而 push 失败：保留该 commit，恢复时推送同一提交。push 成功而后端响应未知：核对真实 ref 与原后端操作，不能重跑 AI 或伪装为已解除。hook 中断：重开后按持久阶段补齐。最终确认后端未知时显示确认待同步，不提前显示全部完成。

用户已授权系统中断后重开继续，无须再次发送通用继续指令。恢复次序：读取本地耐久记录 → 查询原后端操作与当前占用标识／代次 → 核对本地未提交改动、原会话及未知调用 → 按待恢复阶段处理 Git 核验 → 自动继续串行队列。标识已变为未占用时，旧授权不复活；如需继续开发，按空闲规则重新原子领取，不增加 commit 一致性门禁。已有本人有效占用按原代次恢复，待推送／完成操作仍核验远端 ref。账号切换、他人占用、冲突或未知发送不能自动跳过，保留现场并说明实际原因。

“继续”不表示模型进程可从同一 token 恢复。必须通过原生日志核对已发送消息、执行结果和持久现场，不能向新会话盲目重发原指令。具体可靠 ack／查询能力仍须在固定宿主完成验证。

## 5. 当前实现与验收

当前契约和 SQL 持久 commitId、任务受管 remoteRef、claim 身份及代次；后台提供单需求原子领取、真实 ref 成果同步、当前占用查询和管理员置占用／置空闲接口。管理操作推进代次，使旧 hook 与旧整体候选同时失效。Host 在需求接受后自动入队并串行调度，按官方 turn/end 和耐久阶段执行首次／纠偏不同释放时点；桌面 UI 提供逐需求进度、纠偏和最终核对。旧数组扩领协议已删除，自动成果同步不调用整体原型接受或基线流程。

自动化覆盖并发唯一领取、空闲 commit 不一致及 Git 不可达、已占用同 commit 拒绝、缺少 commit 拒绝、同步失败不释放、管理员改标识及旧代次失效、重复 hook、首次／纠偏释放时点、串行推进、未知消息不重发，以及 commit／push／后端同步和完成事件观察后中断的恢复。真实 PostgreSQL 测试使用独立临时数据库；UI 与 Host fixture 结果不等于真实模型或桌面验收。

最终仍须在当前交付版本完成真实桌面 → 原生真实模型 → Host → `100.119.183.44` 指定协同服务 → Git／持久化 → 桌面结果及中断恢复闭环，分别记录版本、实际样本与未验项。并行分支、共享文件、延迟推送及固定宿主原生 ack／flush 的运行证据也须在该闭环核对；文档检查或局部自动化测试不能替代。

## 本地事项登记丢失后的显式进入

进入需求时，本地没有事项记录须先查询当前开发占用。占用归属当前账号与设备、任务仍活动且代次和写入策略一致时，仅从项目既定工作树及官方持久会话查询恢复原事项；工作树分支或会话无法唯一核实时保留现场并说明阻碍。不能释放原占用、另建同需求事项或重发历史指令代替恢复。

恢复仅登记当前可核实的事实，不编造旧轮次、原发送身份或成功结果。恢复后的下一条明确修改／运行指令建立新开发段；与原事项冲突的新建请求保留为未发送的历史，不再进入队列。项目登记集合变化后重新读取对应队列分片，避免旧缓存覆盖新登记项目的既有过程数据。

原生会话的文件边界可跨轮次复用；每次写入重新核对当前开发段、原操作和占用许可，异步核对期间开发段变化则停止写入。不得将会话首次打开时的轮次永久作为后续写入许可。

### 本轮交付边界：跨需求范围仍待实现

移除公开“补充事项”入口不表示已经支持在同一原生会话新增跨需求开发范围。连续对话是交互目标；当前协同契约第 10 章及 Host 的逐需求完成／释放协议仍不支持这一扩领路径。涉及当前授权范围以外需求的请求，须保留输入并说明范围处理尚未完成，不能声称已经取得占用或执行成功。该能力仍需同步契约、后端原子占用、Host 调度及真实桌面闭环后才能交付。

本轮不改变首次开发完成释放占用、后续纠偏重新领取并保留至最终核对的既定规则；不能将多需求对话目标作为静默改变逐需求释放与最终确认语义的授权。
