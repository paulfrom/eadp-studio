# 知识库编码任务提示词

> 用法：把本文件全文作为编码 Agent 的首轮任务提示词。每阶段开始前复制对应阶段段落，阶段验收不通过不进入下一阶段。

## 角色

你是本仓库的编码 Agent，负责把已评审的本地知识库方案落地为可交付的桌面插件能力。你只写产品代码，不重新讨论产品方向；发现方案与代码事实冲突时，先停下来说明证据，不擅自改口径。

## 必读材料

1. `docs/design/local-knowledge/README.md`：唯一方案依据，以 V0.3 为准。
2. `docs/design/local-knowledge/interaction.html`：用户交互口径，业务界面只允许出现其中的日常词汇。
3. `AGENTS.md`：仓库边界、组合优先、提交门禁。
4. `.agents/skills/creating-dsh-plugins/SKILL.md`：插件、工具、slot 契约。

## 不可违反的边界

- 通过官方 slot、service、tool、`agent/pre-step` 扩展；不覆盖、不篡改、不假设官方插件内部实现。接口不足时登记 `docs/blocked-upstream.md`（不存在则新建）并停止该路径，不自行 hack。
- 不新增产品后端、LightRAG 服务、Python 运行时、远端知识空间或多租户体系。
- 不修改 `.local/upstream/` 缓存；确需上游改动只允许走 `apps/desktop-distribution/build/` 的锚定编辑，并完成构建与真实桌面验证。
- 不保留兼容层、migration、隐式 fallback 或并行双实现；被替代路径直接删除。
- 仓库不保留测试代码和测试执行命令；提交前执行 `pnpm check` 与受影响构建。
- `cordis.patch.yml` 变更必须显式声明依赖的 service 与 slot。
- `defineTool` 必须有 output schema 与 render；必填字段用 `required: true`，对象声明 `additionalProperties`。
- 用户可见文案禁止出现 Host、Markdown、OCR、索引、检索、快照、evidenceId、hash、generation 等技术词；使用“文档、导入记录、识别图片文字、整理、查找、本次参考、需求依据、当时内容”。

## 先决验证（编码前置，失败即停止该阶段并报告）

| 编号 | 验证内容 | 通过标准 | 失败处理 |
| --- | --- | --- | --- |
| S1 | 插件注册 `agent/pre-step`，在需求会话每个新 user turn 的首次模型请求前追加一条日志可见消息 | 真实插件 + 桌面会话验证：只注入一次、工具续步不重复、取消与失败可传播 | 记录缺少的公开能力，登记 blocked-upstream，阶段 2 的自动参考改为手工入口 |
| S2 | 富文本编辑器选型 | 支持标题、段落、列表、引用、表格、图片、中文输入法、撤销；与 canonical Markdown 双向转换无结构丢失 | 选下一个候选；不允许用裸 `contenteditable` 作为交付实现 |
| S3 | 任意扩展名接收与解析能力矩阵 | 对每类声称支持的格式给出真实样本、保真结论、失败行为；未支持格式明确进入“需要处理” | 缩小自动转换范围，手工整理路径必须可用 |
| S4 | embedding 接口 | 有真实供应商/模型/维度与一次成功编码记录 | 阶段 3 不启动，词项与精确检索照常交付 |

S2、S3 可以在阶段 1 内完成；S1 必须在阶段 2 前完成；S4 在阶段 3 前完成。

## 阶段一：统一资料与导入

目标：用户能导入任意扩展名文件、得到可编辑文档、失败可恢复；不再出现知识卡正文上限和先标注后保存。

落点：

- `packages/eadp-contracts/src/knowledge.ts`：资料、内容版本、导入项、来源映射契约。
- `packages/eadp-knowledge/src/host/store.ts`：拆分清单提交、正文文件、原件、资源、来源映射、导入项；资料级条件写入。
- `packages/eadp-knowledge/src/host/`：新增导入与转换模块（结构块 + Markdown 渲染）、worker 边界。
- `packages/eadp-knowledge/src/client/`：资料列表、整页明细、导入记录、所见即所得编辑。
- `packages/eadp-knowledge/src/host/index.ts`：先保存正文，标注与整理异步；失败不阻断保存。

验收：

1. 任意扩展名文件可接收；原件先落盘，导入项独立持久化，重启后仍在。
2. 可转换文件生成可编辑文档；不可转换显示“需要处理”，可查看原件、重试、手工整理。
3. 手工整理保存后关联原件，原失败信息保留在诊断。
4. 无模型时仍可新建、编辑、保存、重开文档。
5. 编辑与阅读样式一致；界面无技术术语；无强制校对或审核门禁，无伪百分比。
6. `pnpm check` 通过；受影响包构建通过；真实桌面完成一次保存、重开、导入失败恢复。

## 阶段二：本地查找与需求依据

目标：资料能被查找；需求沟通中自动提供“本次参考”；用户能把真正采用的内容固定为“需求依据”，知识更新或删除后仍可回看当时内容。

落点：

- `packages/eadp-knowledge/src/host/`：SQLite 索引（`index.sqlite`）与专用 worker；结构切片；中文词项与精确通道；单事务发布索引代次；查询短读事务。
- `packages/eadp-knowledge/src/host/proposals.ts`：搜索返回真实命中片段，而不是正文开头；`read` 从 canonical 文件重读并签发证据标识。
- 证据登记器：自动注入与 `read` 共用；绑定会话、项目、内容版本与真实范围。
- `packages/eadp-contracts/src/requirements.ts`：需求提案增加依据字段与快照标识。
- `packages/eadp-requirements/src/host/proposals.ts`：提案生成时核验证据范围并固定快照；应用时正文与依据同次保存。
- `packages/eadp-requirements/src/host/files.ts`：写入项目 `.eadp/knowledge-sources/` 与 `.eadp/proposals/`。
- `packages/eadp-shell/src/host/session-policy.ts`：保留工具使用提示，不再把提示词当作自动查找机制。

验收：

1. 每个新 user turn 首次请求自动带入经原文核验的候选；工具续步不重复。
2. 本次参考与需求依据分离；浏览或查看参考不产生依据。
3. 需求依据可回读固定文档、引用资源与来源位置；资料更新后提示有新版本，资料删除后仍可看当时内容。
4. 查找失败、未找到、能力未就绪三种结果文案不同，不互相冒充。
5. 索引发布与正文保存解耦：保存成功不等待索引，索引失败不影响阅读、编辑和依据使用。
6. 同资料同范围但正文变化不得复用旧结果；分类、标签等无关元数据变化不重算正文向量。
7. 真实桌面完成：自动参考 → 选择依据 → 保存需求 → 更新资料 → 删除资料 → 回读当时内容。

## 阶段三：向量混合（S4 通过后）

- 接入 embedding，记录供应商、模型、维度签名；索引与查询同签名。
- worker 内 Float32 精确余弦；零向量、维度不符、非有限值明确失败。
- 词项、精确、向量三通道按 RRF 融合；`k`、候选深度、预算由冻结样本确定，先写基线值再调。
- 无向量能力时明确提示“部分资料可能暂时找不到”，不把单词项结果称为混合查找。
- 验收必须给出冻结样本上的召回与精度对照、冷暖耗时与资源占用。

## 阶段四：有来源关系扩展（消融后决定）

- 仅实现有证据的实体关系与一跳扩展；同名实体不全局合并。
- 与“词项 + 精确 + 向量”基线同集对照；无净收益就删除该通道，不保留装饰性能力。

## 交付与汇报

每阶段结束提交：

1. 改动文件清单与职责说明。
2. 契约变化：字段、版本条件、错误码。
3. 实际执行的命令与结果（`pnpm check`、构建、桌面操作）。
4. 未验证项与风险，按事实写，不写“已完成”“已验收通过”。
5. 下一阶段是否满足进入条件。

## 禁止

- 把候选自动写成需求依据，或让模型自报正文、版本、出处成为可信证据。
- 在业务界面暴露索引、向量、快照、证据标识等技术概念。
- 用全局同名合并、模型摘要或图关系代替原文。
- 为了让演示好看而伪造转换成功率、检索效果或进度百分比。
- 擅自升级宿主、修改上游缓存或扩大为协同后端方案。
