# 工作里程碑

依据：`docs/dseign/` 原有设计稿、两份 AI 交互优化稿与各阶段需求文档。整体进度按资产生命周期推进：**项目场景 → 需求协同 → 原型 → 基线 → 交接清单**，严格串行；每个阶段开工前必须先有明确的设计文档，无文档不允许开工写代码。

## 开工门禁：设计文档先行

- 每阶段第一步是产出设计文档 `docs/design/NN-<阶段名>.md`，经确认后才允许写代码；实现偏离设计时先回写文档再改码。
- 设计文档必含五节：**用户目标**（本阶段结束时用户能做成什么）、**桌面端职责**（做什么界面与交互）、**协同后台职责**（哪些端点/存储/投影变化）、**数据与文档格式**（载体、字段、协议）、**验收标准**（可验证的完成判据）。
- 阶段完成的唯一判据是该阶段验收标准逐条通过，不以「代码写完」为准。

## AI 交互优化（2026-10-25 代码实现）

依据：[需求管理 AI 交互优化稿](dseign/需求管理-AI交互优化.html)与[项目场景 AI 交互优化稿](dseign/项目场景编辑-AI交互优化.html)。

- 顶部集中会话与当前主操作：有待审阅提议时打开差异面板，否则进入材料确认。文档按真实章节折叠，身份、业务字段和来源信息按需展开。
- 底部状态条集中门禁、待澄清及一致性；门禁与业务声明在确认面板展示，一致性结论、历史与发起入口移入独立抽屉，运行详情按需展开。场景保留既有授权修复流程，需求沿用自身确认和保存恢复。
- AI 仍提供完整候选正文；Host 计算真实章节差异、稳定变更 ID 和精确增删行数。审阅支持全选或部分章节选择；写入只由按钮提交显式 `selectedChangeIds` 授权，普通聊天回复不授权。未选章节保留原文；章节重排作为全文一项审阅；取消不写入，稍后保留提议。
- 提议继续受正文、模板、项目上下文与已读依据的新鲜度检查保护；空、伪造或重复变更 ID 拒绝写入。部分写入的摘要只描述实际修改，当前 hash 匹配时可撤销该次正文写入；CONTEXT.md 使用同一审阅选择流程并校验该文件与依据。
- 已补充章节选择、取消、重复标题、代码围栏、精确行数、部分写入与撤销及 CONTEXT.md 的自动化回归；完整阶段验收和 Windows 原生走查仍分别记录，不据此宣称整个阶段完成。

### 工作台投影归属与命令截止（2026-10-20）

- **一份投影**：设置各节改为声明同一个 `store` 实例（现为 `client/store.ts`，由 `client/session.ts` 统一读写，见 2026-10-21 修订）；区块不再各自拉取状态。首次答复前显示加载态，失败保留上份投影并给出重试，同步中禁用「重新同步」且只允许一次在途请求。

## 设计稿用语与领域语言映射

按 `CONTEXT.md` 执行，不引入平行词汇：

- 设计稿「草稿编辑中 / DRAFT_IN_PROGRESS」→ 确认状态为草稿，任务状态为处理中。
- 设计稿「已固化基线 🔒」→ 确认状态为已确认（固定版本）。
- 设计稿「待补全项」→ 区分材料自身的核心与非阻断待澄清项；场景仅由使流程无法确定的问题阻断确认，具体规则留到需求；需求按自身核心规则及验收条件判断阻断。「规则分歧」若来自独立一致性对比，则归入后台冲突摘要，不自动变成材料核心问题，也不阻止流程。
- 设计稿「置信度」→ AI 辅助评审产物，仅作用于可选评审过程，不构成确认。
- 设计稿「采纳」→ 写入提议的章节审阅：AI 归纳结论并提供完整候选正文，Host 生成章节差异；用户勾选章节并点击写入后更新本地草稿。材料确认是后续独立动作，须由可信 Host 执行并由后台接受。

## 隐形需求与实现边界

**AI 能力边界**：模型接入由 DSH 宿主统一配置（StudioSettings models 节已明示「工作台不另建模型接入层」），`collaboration-api` 不新增 AI 端点。「后台 AI 开发」指 Host 侧的会话编排、结构化协议解析、写入提议、章节差异与审阅写入。普通对话只讨论和提议，不直接写文件；AI 提供完整候选正文，Host 生成可审阅的章节差异，只有用户点击写入按钮并提交显式所选变更 ID 后才消费提议，聊天回复不授权。结构化输出已有两个已验证先例可沿用：`eadp-candidates`（场景拆分候选）与 `eadp-review`（评审意见）文本协议；**本轮修订**：内置协作方法 `grill-with-docs`（上游技能快照固定在本仓库 `.local/skills/mattpocock/`，含 `grill-with-docs`、`grilling`、`domain-modeling` 三个 skill），其原产出的术语与规则写入用户业务项目根目录 `CONTEXT.md`，不产出 ADR。

**原型指标语义**：设计稿卡片指标对应关系——「BDD 契约 N 项」= 需求文档规则条数（阶段二推导）；「仿真（已模拟/联调中）」= 模板 mock 围栏检查结果（模板是自研 `requestMock` 运行时而非 MSW，沿用现状、卡片文案表「仿真」语义，不引入 MSW 依赖）；「原型验证（验收完）」= 原型确认状态（阶段三回流）。需求规则 ↔ 原型页面/mock 的一致性自动检查涉及契约-路由映射设计，不绑定阶段，列为后续决策点。

**场景设计决议（2026-10-20 整体确认，2026-10-25 按 AI 交互优化稿修订）**：

- 项目场景承载一组细化需求的共同业务范围。需求沿用场景关联；现有项目场景体系中固定内置“通用场景”，仅供新增需求时选择，不在场景目录显示、不开放正文和编辑入口。普通来源保留固定确认版本，通用场景的真实初始引用由项目初始化系统接受，与用户确认分别记录。
- 用户先命名场景，创建空白 Markdown 文档；左侧与 AI 协同，右侧预览并允许手工编辑当前 MD。场景使用 Markdown，HTML 中的 YAML 文件示例不再作为载体约束；业务流程允许分支、退回及重试，不强制无环。
- 场景不使用分类，新建与确认均不要求分类，也不提供场景分类筛选；由后台按项目递增分配稳定业务编号，如 `SC-0001`。编号项目内唯一、不可手工修改、不回收，改名和修订不变；UUID 继续作为内部技术身份，界面主要显示业务编号。后端已分配稳定业务编号，桌面已消费该编号；材料路径继续使用 UUID。阶段二已另行确认需求也不使用分类，并使用稳定 `REQ-0001` 编号，需求实现尚待修改。
- 新增项目共用的场景模板设置，模板随项目版本保存：内置默认 MD 模板，包含目标与范围、角色、流程、业务规则、异常、验收条件、依据及待澄清项；支持用户上传 MD 模板。新建场景保持空白正文，AI 按模板提供完整候选正文，Host 生成章节差异，用户勾选章节并点击写入后更新草稿。
- 每个场景绑定所选模板固定版本；更新设置只影响新场景，已有场景由用户显式切换，不能自动改写 MD。新增仅影响本地、可手动切换的“模板结构检查”开关，默认关闭，不同步为项目强制规则；开启时检查所选模板二级章节齐全，允许重排和新增，不从模板文字推导业务门禁。场景流程完整性、版本、权限及后台接受等固定条件始终执行，资料与引用仅提醒。
- 手工编辑停止输入后自动保存本地 MD，审阅写入时也保存；切换场景或退出前确保保存完成，失败时保留输入并提示。保存草稿不构成场景确认或正式远端同步。
- 每个场景保留独立会话历史；新会话继承当前 MD、所选模板版本及当前选定资料，不自动带入完整旧聊天；旧会话保留并可恢复。
- 场景会话回答以可读中文说明为主（改什么、为什么、依据哪些已读资料、还缺哪些业务答案）；机器可读协议块只在需要 Host 校验或落盘时置于回答最后，纯提问不输出块，且不回显被替换的原文。
- 自动保存遇到外部文件变更且页面有未保存输入时，保留两份并展示差异，用户选择或合并后再保存；冲突未解决时暂停确认并禁止启动自动修复。若已处于授权修复任务中则终止任务，解决冲突后不自动恢复。
- 写入提议支持全选或部分章节选择。用户审阅后点击写入按钮提交显式所选变更 ID，Host 校验并保存合成正文；未选章节保留原文，章节重排作为全文一项。同一提议重复提交只生效一次（幂等）。正文 hash、模板固定引用、项目上下文内容 hash 或所选依据集合任一变化即提议作废，须基于最新 MD 重新生成。
- 不提供「自动写入 AI 建议」开关。写入只能由审阅面板的按钮提交非空且有效的所选变更 ID；普通聊天回复不授权。取消不写入，稍后保留提议；Host 校验正文 hash、模板固定引用、项目上下文 hash、所选依据与变更 ID 后保存所选修改，返回实际变更摘要；当前 hash 匹配时可撤销本次正文写入，失败保留输入与原因。
- 资料范围包括文本／Markdown、PDF、Word、Excel、PowerPoint 和图片；每份资料区分已读取、部分读取和失败，AI 只能引用实际读取的内容，上传成功不等于已读取。当前 Agent 资料读取链路仍须实现与样本验收。
- 普通对话整理中，AI 首稿及修改均先提供完整候选正文，经用户逐章审阅并点击写入后更新草稿。记录文件 hash，内容变化时重新读取；AI 不能自行判断已获写入授权，条件变化后的提议作废，须读取最新 MD 后重新提问，禁止直接覆盖。
- 仅用户选定的正式依据随确认场景归档，保留来源与 hash；会话和临时资料留在本地。
- 用户最终确认场景并由协同后台接受后，选择立即或稍后拆分。立即拆分先生成候选，用户选择后才创建需求草稿，需求须独立完善与确认；稍后拆分保留已确认场景上的入口。
- 场景确认遇到阻断时，用户可点击一次“AI 修复并确认”，授权本轮基于已有依据修正结构、引用及内容，直接写入后重算 hash、执行完整门禁并由可信 Host 自动再次提交确认，无须再逐轮审阅并确认写入。缺失业务答案时暂停询问用户。
- 自动修复最多 3 轮；相同阻断无改善、缺少可读取依据或发生并发编辑时提前停止，保留现场并说明原因。仅后台已接受才显示已确认；接受结果未知时先核对状态，不盲目重复确认。
- 缺少业务答案时暂停；用户提交“补充并继续修复确认”后续接同一任务，累计最多 3 轮，重读并重检版本、权限及占用。普通聊天回复不自动恢复；暂停期间若文件被修改，终止旧授权并保留现场。
- 草稿名称和占用状态对其他项目成员可见；草稿正文和会话留在本地。修订期间其他成员继续读取旧确认版及修订／占用状态。
- 已确认场景先只读打开；用户点击“开始修订”，查看影响清单后仅占用当前材料。2026-10-21 用户确认取消整体关联冻结和强制同批确认；修订不自动改关联内容。一致性对比作为独立能力，只留当次结论与冲突摘要，不阻止材料流程。
- 卡片分别展示创建人、当前编辑人及修订状态，确认详情展示确认人和时间；本阶段不新增业务负责人指派或转交。
- 用户已于 2026-10-20 整体确认阶段一设计（含工程方案），作为实施依据；设计开工条件已满足，后端修正已落地并开展隔离验证，桌面与 Host 代码改造已完成；本轮仅做代码校验，38 条完整产品验收未执行。

## 阶段一 项目场景（形态奠基）

**当前执行顺序**：先完成协同后端修正，再开始桌面端修正。后端关系存储、编号幂等、固定 Git 校验、需求来源、修订批次、模板独立发布及修复授权控制已落地；桌面与 Host 已完成契约、编辑、会话、资料、模板及修复确认代码改造；按用户要求仅做代码校验，阶段一完整产品验收未执行。分类清单、接口边界及验证记录见[阶段一修正与验证记录](design/scenarios/implementation.md)。

上述“修订批次”及现有需求分类描述当前实现；阶段二目标已取消关联冻结、强制同批确认、自动来源升版与需求分类，须按阶段二设计替换，既有代码校验不证明这些新规则已经落地。

设计文档：[项目场景设计](design/scenarios/01-scenarios.md)。**设计已于 2026-10-20 由用户整体确认，按协同后端、桌面端两类串行修正。** MaterialCatalog 已纳入 HEAD，作为现状参考。

**用户目标**：用户先为业务场景命名，生成空白 Markdown 文档，通过左侧 AI 对话结合所提供资料推理和设计，归纳本轮结论后审阅章节差异，勾选变更并点击写入后更新右侧 MD，或手工编辑；门禁通过后确认场景，由协同后台记录已接受的固定版本，再选择是否立即拆分更细节的需求。

**设计文档必须覆盖**：

- 桌面端：场景列表（卡片信息结构：确认状态徽章、创建人、当前编辑人、修订状态、资产编号；筛选 Tab；统计汇总条；分页）；命名后创建空白 MD；场景模板设置（内置默认、上传 MD）；双栏工作区（左对话 + 右 Markdown 文档、预览/源码编辑、导出、折叠为全屏对话）；资料输入与正式依据选择；门禁状态条与 Working Tree 展示；场景智能体交互（完整候选正文、章节审阅与所选变更写入、内置 `grill-with-docs` 协作方法及其 `CONTEXT.md` 术语、新会话、快捷引导指令、模型标识）；场景确认按钮及确认后的拆分需求选择；确认版只读查看及影响确认后的显式修订。
- 协同后台：场景实体、编号、占用、确认、固定版本既有链路的差距核对（`EntityView` 展示字段扩展、确认状态投影）；取消场景的分类字段及必填校验，不以默认分类保留旧约束。
- 数据与格式：场景 Markdown 载体及内置／上传模板（路径、元信息及模板应用规则按已确认设计执行）；文件 hash 记录、变化后重读及提议作废约定；写入提议的字段（提议 ID、目标文件、正文 baseHash、模板固定引用、项目上下文内容 hash、已读依据 ID 集合、Host 生成的章节差异及显式 selectedChangeIds）；正式依据来源与 hash；需求至少一个固定场景来源的约束。

**代码实现范围**：沿用现有 MaterialCatalog 及 Markdown 材料链路补齐差距，按已确认设计取消场景分类、增加项目内业务编号并调整解析与校验；双栏工作区重构；场景智能体专属 preset、写入提议、精确章节差异与所选变更写入命令（含 `newSession`）；文件 hash 跟踪与重读；门禁聚合、授权修复续接及场景确认串联 Git 固定版本和后台接受；确认后由用户选择是否发起需求拆分。

**验收**：命名场景 → 创建空白 MD → 提供资料并对话整理 → 用户审阅并显式写入所选章节／手工编辑 → hash 变化后重读 → 门禁通过 → 用户确认 → 后台接受 → 选择立即拆分或稍后处理，全程可用；使流程无法确定的问题存在时阻断场景确认；具体规则待需求确认、资料缺失不阻断；场景 Markdown 解析校验与需求阶段既有行为通过相应验证。

本阶段同时是形态奠基：列表范式、双栏工作区、门禁状态条、固化动作、写入提议＋章节审阅写入均在此阶段落地，后续阶段复用同范式做增量。

## 阶段二 需求协同

设计文档：`docs/design/02-requirements.md`。

**用户目标**：从已确认普通场景拆分形成需求，或命名后选择普通场景／内置通用场景新建空白正文需求；所有需求均有真实场景来源。与「需求设计智能体」对话整理需求 Markdown，规则与验收推荐使用前提、触发和结果表达，保留实际来源依据并独立确认固定版本；需求列表呈现规则条数、待澄清项、最近对比结论及确认状态筛选。需求材料确认不称为原型基线。

**设计文档必须覆盖**：

- 桌面端：不含分类的需求列表（稳定编号、场景关联芯片、指标徽章、筛选 Tab）；独立需求模板及 Markdown 文档面板；需求智能体会话（复用阶段一写入提议＋章节审阅写入与双栏骨架，换专属 preset）；确认按钮与材料自身门禁（无悬空场景引用）。
- 协同后台：需求实体、稳定业务编号、前置需求校验与环检测（`validatePrerequisites`）、scenarioIds 双向关联与固定版本来源校验；取消需求分类及词表；复用模板目录与发布能力；一致性对比的关联目录、当次结论与冲突摘要存储与查询，后台不拉取 Git 内容做对比。删除整体关联冻结、强制同批确认和自动关联来源升版，保留单资产占用、独立接受及各自版本校验；对比结论不参与材料确认。
- 数据与格式：用户工程 `需求/<名称>.md`，沿用 Markdown 和 `eadp-metadata` 身份块；`REQ-0001` 只作稳定业务编号，不作为文件名。独立需求模板引导正文，GWT 推荐但不强制；规则条数、待澄清项与后端冲突数量分别统计，不把冲突写成材料的 blocking 问题。

**验收**：需求↔场景双向关联及固定来源校验生效；通用场景具有真实系统预置版本，仅新增需求时可选，场景目录与统计不显示、不开放正文或编辑入口；手工新建需求正文空白，候选业务内容进入需求草稿且可追溯到来源片段。各材料独立修订／确认，不冻结或自动改写关联内容。手动及确认后自动对比只读本地当前文件、不调用 Git、不自动补齐缺失文件；每次对比的结论与冲突摘要存后台，不设处理状态，不改写文件、不阻止流程、不要求复比或先完成材料确认。检查失败或旧结果不影响材料按自身条件确认；真实修改经用户审阅并显式提交所选变更 ID 后才写草稿；未选章节保留原文，取消和聊天回复不写入。权限、并发、提醒及失败恢复的判据见[需求协同设计](design/02-requirements.md)，不以旧批次行为代替验收。

## 阶段五 交接清单

设计文档：`docs/design/05-handoffs.md`。

**用户目标**：从基线一键生成交接清单材料，AI 会话完善交接内容，研发侧收悉回执，交接状态全程可追溯。

**设计文档必须覆盖**：

- 桌面端：交接阶段目录/详情、生成入口、收悉状态展示。
- 协同后台：generateHandoff 链路、receipts 回执端点差距核对。
- 数据与格式：交接材料载体与字段。

**验收**：基线 → 交接清单 → AI 完善 → 确认 → 研发收悉全链路走通。

## 阶段六 端到端验证与桌面发行

设计文档：`docs/design/06-verification.md`（验证与走查方案，同样先于验证工作）。

- `tests/collaboration/` 与 `tests/windows-desktop/` 回归更新：新文档格式、写入提议与章节审阅写入、双栏交互、固化阻断、指标回流。
- `pnpm dev:desktop` 人工走查：逐项对照四份设计稿，覆盖五阶段全流程。
- `./build-desktop.ps1` 生成安装包并做干净机安装冒烟。
- 验收：全部测试通过；走查问题清零；安装包产物含 SHA256 记录。

## 依赖与顺序

严格按资产生命周期串行：阶段一 → 二 → 三 → 四 → 五 → 六，不并行开阶段。阶段一是形态奠基（列表、双栏、门禁、固化、写入提议＋章节审阅写入），后续阶段复用范式只做增量，这也是串行能成立的前提。每阶段以设计文档确认为开工条件，以验收标准逐条通过为完成条件。跨阶段通用决策点（需求规则与原型 mock/页面一致性自动检查、契约一致性统计指标）不绑定阶段，另行立项。
