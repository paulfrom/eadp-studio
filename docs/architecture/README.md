# 技术架构图

`eadp-studio-architecture.drawio` 是项目的技术架构图，单文件三页，用 draw.io / diagrams.net 打开即可编辑。

与 `docs/product-blueprint/` 的产品构想图分工：产品图回答"为什么做、做什么、谁来做"（业务语言）；本图回答"由哪些部件组成、怎么连、怎么造出来"（实现语言）。两图不重复论证，也不互相矛盾。

## 三页各回答什么

| 页 | 抽象层级 | 内容 |
| --- | --- | --- |
| 1 容器视图 | C4 L2 | 可部署单元、用户、数据存储与外部系统，以及它们之间的协议 |
| 2 组件视图 | C4 L3 | 界面半边、本地执行层、协同服务三个单元的内部组件与共享层 |
| 3 发行装配链 | 构建期 | 固定上游 → 装配 → 改写 → 构建 → 校验产物 |

每页只表达一个抽象层级；第 3 页不是运行时层级，页眉与印章都写明了这一点。

## 读法

- **卡片**：上方是大写类型（CONTAINER / COMPONENT / DATA STORE / EXTERNAL SYSTEM / PERSON / SHARED LIBRARY），中间是名称与职责，右下角是技术脚注。
- **关系徽标**：两行，第一行是动作，第二行是协议 `[协议]`。颜色区分关系性质：主流程、状态变更、数据读取、异步依赖。
- **系统边界**：虚线框只包可部署单元；人员、外部系统、数据存储都在边界之外。
- **印章**：右上角标注本页的 C4 层级与评审状态（草案）。

## 约定

- 图上不标"代码就绪 / 未发行验收"一类状态；固定版本只出现在第 3 页，因为那里讲的就是版本锁定。
- 外部系统（代码托管、模型服务、发布目标）不画内部结构，需要时看它们在第 1 页的关系。
- 徽标是独立单元格，不随连线自动移动；移动连线后需要手工把徽标移回空白处。

## 校验

图的几何预算由脚本核对：卡片不重叠、连线不穿卡片、每条连线最多两个拐点、节点间距不小于 40px、徽标不压卡片。改动后请重新核对。
