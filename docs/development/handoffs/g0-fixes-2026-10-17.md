- 占用视图在 Host 授权后投影为严格五字段 token，再发送确认、取消及关系变更请求；不把 owner、用途和展示字段混入 API 请求。保存时新认领的任务先重新读取有效占用。

## Linux 更新协同后端

若当前服务使用仓库现有 Compose 部署，在仓库根目录执行：

```bash
git status --short
git switch main
git pull --ff-only origin main
git log -1 --oneline
docker compose --env-file apps/collaboration-api/.env \
  -f apps/collaboration-api/compose.yml up -d --build api
docker compose --env-file apps/collaboration-api/.env \
  -f apps/collaboration-api/compose.yml ps api
curl --fail http://127.0.0.1:6972/health
```

保持实际 `.env`、数据库卷和运行方式；本轮无数据库 schema 变更，不需重建数据库。端口按现有配置调整。systemd 或其他镜像部署使用原有管理方式替换 API 并重启，不另起 Compose 抢占端口。健康检查只能证明服务及数据库可用，还需测试业务流程。

Linux 可检查通用代码、构建插件资产和重建后端；仓库 `scripts/build-desktop.mjs` 只支持 Windows x64 原生发行构建，不能在 Linux 上据此生成 Windows 验收包。
