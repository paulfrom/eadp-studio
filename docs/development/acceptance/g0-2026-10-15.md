## 缺陷与阻断清单

### A01 · P1 · Windows 验证件与当前源码不一致

已重新计算现有安装程序 SHA-256：`59d583377f44451b75472a04ada5024efea95f604bd0c55883cf66df54b9b9ff`，与 `artifacts/windows/SHA256SUMS.txt` 一致。实际安装 ASAR 的 SHA-256 为 `e8f0156975f2f00665104293e7ef4e6afaeacfb6b4045b8994b90acf189ae5fe`；从中提取的 Studio Host 为 `function apply() {}`，运行时不存在 `studio-tools`。

当前 [composition.ts:38](../../../packages/studio-plugin/src/host/composition.ts#L38) 要加载该工具目录中的 manifest。旧首启、模型、审批和恢复证据仅证明当时的最小插件，无法证明后续提交的完整 Studio 已装入制品。

复验要求：从修正后固定源码构建新验证件，记录新包及 ASAR hash，核验真实 Host/client、模板和工具清单，再执行原生登录、任务、检查、预览与恢复；不复用旧包 hash。本项不要求签名、升级或卸载。

### A02 · P1 · 可写路由 TS 可以绕过文件执行边界

[manifest:385](../../../packages/studio-plugin/assets/prototype-template.manifest.json#L385) 允许修改 `config/router.config.ts`；[config.ts:3](../../../packages/studio-plugin/assets/prototype-template/config/config.ts#L3) 在构建配置加载时直接导入该模块。[template.ts:119](../../../packages/studio-plugin/src/host/prototype/template.ts#L119) 的保护文件哈希检查不能约束该可写模块的顶层副作用。

无害复现：完整复制模板后，只向允许修改的路由 TS 追加 `node:fs` 写入验收自有、工程外层的标记文件。真实 guard 返回 `ALLOWED`，真实契约检查接受，真实 tsx 模块加载退出 0 并写入该标记。环境变量裁剪和进程树管理不构成文件/命令隔离。

证据边界：没有执行完整 Umi 构建或原生 DSH；复现的是 Umi 配置直接导入的同一 TS 模块在真实 Node loader 下的副作用。需修正可写内容到宿主执行的信任边界，再验证实际安装、构建及全部 Agent 执行入口在执行前拒绝越界行为；不能只增加提示词或构建后检查。

### A03 · 已撤销验收阻断 · 数据库和登录路径只支持一个协同账号

[schema.sql:3](../../../apps/collaboration-api/db/schema.sql#L3) 使用 `CHECK (id = 1)`；[session.ts:26](../../../apps/collaboration-api/src/auth/session.ts#L26) 固定查询测试账号。当前实现不能承载第二位独立作者，因此无法完成 G0-6 双作者、管理员释放后换人占用和身份隔离验收。

用户已明确数据库不用双作者协同验收，本轮不要求扩展账号或增加双作者用例。此段仅保留首次审计事实，不再作为 G0 阻断或 Windows 修复任务。

### A04 · 外部前提未闭环 · 真实 GitLab 账号绑定仍缺成功证据

[最新交接:25](../handoffs/studio-auth-projects.md#L25) 记载：精确邮箱搜索无匹配，用户名 `songlin.liu` 的数字 ID 70 无法证明邮箱归属。当前首次登录在 [session.ts:36](../../../apps/collaboration-api/src/auth/session.ts#L36) 调用严格精确解析；离线拒绝用例通过不代表真实绑定成功。

### A05 · P1 · 浏览器/Mock 检查失败后仍可启动预览

[composition.ts:62](../../../packages/studio-plugin/src/host/composition.ts#L62) 在 `checkStaticPreview` 成功前缓存工程结果；失败后 [composition.ts:112](../../../packages/studio-plugin/src/host/composition.ts#L112) 仅凭该缓存启动预览，跳过原生静态页面验证。

已提取实际闭包、注入静态验证异常并复现预览成功。此为离线控制流复现，不代表已执行 Electron。复验应覆盖检查失败后立即预览、旧成功结果后重检失败、输入/产物变化及正常通过路径。

### A06 · P1 · 拆分请求失败后，重试跳过需求候选生成

[application/studio.ts:272](../../../packages/studio-plugin/src/host/application/studio.ts#L272) 在发送 prompt 前持久化 `splitEvents`。prompt 抛错后，恢复入口 [studio.ts:260](../../../packages/studio-plugin/src/host/application/studio.ts#L260) 据此跳过拆分。

实际 `StudioApplication` 配合内存端口故障注入已复现：失败被记录，后续不再调用 prompt。需区分任务已建立、请求失败及完成状态，验证同一确认事件既可续办失败任务，又不会重复生成已完成候选。

### A07 · P1 · 孤立 Git 状态没有阻断新的生产认领

[service.ts:88](../../../apps/collaboration-api/src/service.ts#L88) 的 claim 路径只验权限和数据库领域条件；[occupations.ts:39](../../../apps/collaboration-api/src/modules/occupations.ts#L39) 的管理员释放会将 prepared 操作置 aborted。当 Git 已写入但后端未接受时，新认领没有核查实际稳定头与认可头分歧。

真实 service/repository/domain 配合内存 SQL/GitLab adapter 已复现：认可头为 `a…`、实际头为 `b…`、旧操作 aborted 时，新 prototype claim 成功；实际头读取和集成状态查询均为 0。合成 actor 绕过登录，不代表真实 PostgreSQL 竞态或 Git 故障时序验收。需在真实在途合入/管理员释放/响应丢失场景验证后继阻断及核对恢复。

### A08 · P2 · 其他成员可读取尚未确认的需求信息

[service.ts:52](../../../apps/collaboration-api/src/service.ts#L52) 返回全部实体，未按作者及确认状态裁剪。离线注入不同 actor 后，其 state 返回了 owner1、materialVersion=0、draft 的合成私有标题；不符合架构要求的其他成员仅见占用状态。

需补跨作者、跨角色查询负向验证；此处已证明的是标题/实体元数据泄露，没有声称读取了完整 MD 正文。

### A09 · P2 · 新确认场景版本的候选被旧候选阻止

[application/studio.ts:286](../../../packages/studio-plugin/src/host/application/studio.ts#L286) 只按 scenarioId 去重。旧候选仍在时，新输入对应的新会话输出被静默丢弃。已用实际类方法复现；需按固定确认版本/拆分任务验证候选归属、过期输出和重放，保留已采用结果的来源。
